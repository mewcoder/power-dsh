# 插件更新

## 标识、入口与范围

功能 id `plugin-updates`。PowerDSH 设置页底部显示本插件的运行版本与「检查更新」按钮，各分类共用一处。在「其他」提供独立持久化开关 `pluginUpdatesEnabled`，默认开启；关闭仅隐藏此入口，不改变安装来源和已经交给市场的任务。功能不检查 DSH 宿主更新，不自动安装或定时检查新版。

## 配置与行为

用户主动检查时先核对本插件最新正式版；运行版本与正式版相同或更高时显示「当前版本无需更新」并直接返回，不要求市场刷新远端元数据。确有新版时再发现同源 dsh-market 的公开 update API v1，要求正确 schema、检查／更新／进度能力和已核对的端点。本轮按市场 `1.73.19`、提交 `da774820fd49f4915461ff2031eedbef9b48dfe7` 的 `UPDATE-API-V1.md`、`routes.ts`、`update-api-v1.ts` 实现；该 API 当前为 beta，缺席、旧版、鉴权失败或结构改变都明确提示通过插件市场处理，不调用旧版私有 mutation。

只查询 `power-dsh`。正式版本由 owner-only `readPluginRelease` 读取：Host 经已核对的 subprocess 执行固定仓库的 `git ls-remote --tags`，解析普通／annotated tag 及 peeled commit；再匿名 HEAD 查询 GitHub 的公开 `/releases/latest` 与该版本固定附件 `power-dsh.tgz`，只接受正式版本标签和官方 HTTPS 附件跳转。不调用 GitHub REST API，也不把最新 Git 提交或尚未发布的标签当成正式版。Git 命令禁用交互与凭据助手，不读写用户 Git 配置，不 clone、checkout 或修改仓库；当前 Host 没有 Git 时明确提示，不新增运行依赖或自动安装 Git。

市场的 Git 来源版本可能是提交号，须核对市场目标提交等于正式 Release 标签解析后的提交，才能显示「更新到 x.y.z」。归档路径的版本须与正式 Release 版本一致；local／linked／generation 可以只读比较当前正式版本，但不在此处转换来源或提供安装。没有可靠目标显示「未确认可用更新」，不能把读取失败或未知版本说成已最新。

有新版时显示目标版本、官方 Release 更新日志链接和「更新」按钮。点击打开宿主公共 Modal，显示当前 → 目标版本及可能需要刷新／重启的说明；取消不写入。确认时重新检查目标和安装基线，变化则要求重新检查，不静默接受另一个版本。POST 只发送固定包名，市场持有安装、兼容检查与恢复；本插件不停止自己、不执行 pnpm、不写 profile manifest、patch 或文件，不绕过市场发布等待和运行中任务保护。

市场接受后按 operationId 查询其公开进度，只有返回成功且安装版本达到已确认目标，才显示更新完成；要求刷新或重启时明确说明并提供用户主动的界面刷新入口，不自动重载或退出。失败、取消、回滚、记录丢失和无法确认完成分别显示，保留可恢复状态，不自动重发 mutation。网络失败后的更新状态可能未知，应到市场确认，不能再次直接发起安装。

## 生命周期、权限与兼容

常态不发网络请求；仅用户检查或恢复本页面已记录的更新任务时请求。市场发现与更新请求走当前页面同源、保留代理路径前缀、携带原生会话 cookie、禁止重定向。GitHub 公开 HEAD 请求在 Host 中匿名执行，只读取受限跳转元数据，不下载附件或携带 cookie。页面只在配置 ready 且 writable 时允许检查与更新。关闭页面／开关取消本页面的读取与进度定时器、忽略迟到结果；已经发出的只读 Host 查询最多二十秒，Host 卸载则取消进程和网络请求，不影响市场持有的安装。已接受 operationId、确认版本和市场 bootId 仅暂存在当前标签页 sessionStorage，并按页面路径隔离；重新打开时校验同一 Host bootId 后继续读回，不以旧记录操控新 Host。存储失败不撤回已经接受的任务，提示到市场确认。

错误使用共享反馈与固定双语文案，保留检查结果；不显示原始 HTTP 响应、路径、配置或进程输出。不会因超时自动重试更新。未知或更高版本、开发版本不提供降级；不提供自建下载器或替代重启机制。Inspect 本轮不可用，宿主依据为已核对 `0.2.2-rc.1` 同源转发、公共 Button／Modal、configForms、subprocess 的托管生命周期与 `collected.stdout.readFrom(0)` 契约；不引入私有安装接口或生产依赖。

公开页面的 429 或具有明确限流响应头的 403 显示「接口请求过于频繁，请稍后重试」，按 `Retry-After` 等待，无明确时间时至少等待一分钟；Host 保留等待截止时间，并在当前标签页保存冷却，手动重查和重新加载均不在冷却内重新请求 GitHub，不安排自动重试。普通 GitHub 失败不误导为 DSH 登录或管理权限错误；只有同源市场鉴权失败使用权限提示。限流或缺少 Git 时提供公开发布页链接。正常启动及打开设置仍为零更新检查请求，无需新增「自动检查」开关。

## 验收条件与验证

测试覆盖默认零请求、只读／开关、Git 缺席、标签解析、正式 Release／附件校验、当前版与新版、重复点击、确认与取消、目标变化、市场 API 缺席／错误、限流等待、任务进度与实际版本、刷新／重启提示、sessionStorage 恢复和 Host 变化、卸载及迟到响应。静态检查和内存测试不等于真实插件自更新验收；本轮本地安装与页面结果另记兼容性记录，不执行真实在线升级或自动发布。
