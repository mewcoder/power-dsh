# 工作区管理

模块 id：`projects`；主开关 `projectManagerEnabled` 默认 `false`。模块的[定义](definition.ts)、[配置](config.ts)、[Host](host.ts)、[Client](client.ts)与[行为测试](tests/)在本目录维护。当前为**已实现源码**，实际安装与页面验收尚未执行。

## 标识、入口与范围

在 **设置 → PowerDSH → 管理** 打开「工作区管理」开关，设置侧栏新增独立 **工作区** Tab（与技能、MCP、全局指令、已归档同样的 `settings.section` 接入方式，`order: 56`，图标为 Lucide Folders）。开关说明为「查看和移除工作区」，页面顶部说明为「查看工作区」。开关默认关闭、独立持久化，只控制工作区页入口。页面复用「已归档」列表外壳（760px 最大宽度、18px／600 标题、13px 说明、通栏搜索框与公共 `Menu` 下拉），不另造页面框架。

目标：让用户在一个页面里看到 DSH 当前登记的全部工作区、各自目录、会话数与最近活动，并能把不再需要的工作区从侧栏和工作区选择器中移除，而不去逐个折叠侧栏分组。

保留：工作区（原生实体为 `Workspace`）登记、会话归属与磁盘文件都属于宿主能力，本功能只读展示并调用原生移除。明确不包含：新增或重命名工作区、工作区筛选下拉、按使用时长或设备筛选、远程设备列表、批量选择与批量移除、跨工作区移动会话。这些相邻能力均已与用户确认排除；「疑似不再使用」复核卡片与设备列同样按用户要求不做。

## 配置与行为

唯一配置键 `projectManagerEnabled`（`z.boolean().default(false).volatile()`，与现有开关一起经宿主 `configForms` 持久化）。工作区数据归宿主，本功能不另存、不缓存到配置。

- 打开页面即读一次完整工作区集合；窗口重新获得焦点时再读一次，保证宿主导航产生的变化可见，并同时刷新相对时间。
- 每行显示工作区名称、实际目录、会话数与最近活动。目录取自原生 `workspaceController.follow(signal)` 基线的 `items[].path`，单行省略并随宽度伸缩，完整路径经原生 `Tooltip` 悬停与键盘聚焦查看；名称同样经 `Tooltip` 显示全文。目录缺失（旧 Host 未提供）时省略该行，不补占位或猜测路径。
- 会话数取该 Workspace 的 `sessionIds` 长度，包含已归档会话；不额外过滤，避免与侧栏数字不一致。
- 最近活动取该 Workspace 全部会话中最新的一次活动时间，来源是原生会话列表 `sessionController.list()` 的 `updatedAt`（与侧栏行的时间同源，已含最后一次用户提示）。没有任何会话或会话都无时间时显示「未使用」。
- 相对时间沿用原生会话行的时间分桶（刚刚／分钟／小时／天／个月／年），随浅深主题与语言切换；时钟偏差导致的未来时间按「刚刚」处理。
- 排序支持「最近活动」与「手动排序」两种，只影响本页行顺序，不写回宿主。默认「最近活动」：按最新活动降序，同值与未使用的工作区保持原生登记顺序；「手动排序」完全沿用原生 `workspaceIds` 顺序，与侧栏一致。
- 搜索框占位文案为「搜索工作区」／`Search workspaces`，与它实际能搜的内容一致；只在工作区名称与目录上做本地过滤，不按设备、会话内容或文件夹内容搜索。空查询展示全部；无结果显示「未找到匹配的工作区」，完全无工作区显示「暂无工作区」。
- 行尾「移除」为文字按钮，尺寸、圆角、描边、错误色与 hover 对齐原生「设置 → 模型」的 `dangerButton`：28px 高、`--dsw-radius-sm` 圆角、`0 10px` 内边距、12px／18px 文字、透明描边加错误色文字与 `--dsw-alias-interactive-bg-hover-danger` 悬停，可访问名称带工作区名称。
- 「移除」先弹出原生 `Modal` 二次确认（展示工作区名，说明会话与磁盘文件不受影响），确认按钮沿用同一危险样式，不伪装成主按钮。确认后调用原生 `workspaceController.delete({ workspaceId })`：只删除登记，目录与会话日志保留，会话回到「未分组」并仍在最近与搜索中。成功后以 Host 返回的最新工作区集合重载页面，该项从列表消失。
- 移除期间该行按钮置为忙碌并禁止重复提交，其余控件保持可读；失败保留可恢复状态并给出对应提示，可再次操作。
- 加载失败显示可重试的页面级错误，不显示为空列表。

## 生命周期、权限与兼容

- 关闭开关即移除工作区 Tab 与图标；卸载释放订阅与监听。工作区登记、会话归属与开关偏好保留。
- 只读工作区登记、会话计数与会话活动时间；移除时经原生控制器删除一条工作区登记，不触碰工作区文件或任何会话日志。无网络、无进程、无凭据。
- 原生接口依据（本机 DSH `0.2.2-rc.1` Inspect 与安装包源码核对）：`workspaceController.follow(signal)` 基线帧 `items[].{workspaceId,title,path,sessionIds}`；`workspaceController.delete({ workspaceId })`（`WorkspaceCommands.delete`，保留目录与会话，未知 id 返回 `workspace/not-found`）；`sessionController.list({}, signal)` 的 `items[].{sessionId,updatedAt}`（`updatedAt` 即 `max(createdAt, lastPromptAt)`）。
- 服务缺席（例如无 `workspaceController` 的宿主）时，Host 方法抛 `projectsUnavailable`，页面显示「工作区管理暂不可用」，不伪造空列表或成功状态。会话列表缺席只让最近活动降级为「未使用」，不阻止工作区列表显示。Host 通过可选 `ctx.inject` 获取两个服务，缺席不会阻止其余功能加载。

## 验收条件与验证

可观察条件：
- 开启开关后出现「工作区」Tab 与其图标，关闭后两者消失，且不增加重复监听或订阅。
- 每行显示工作区名称、实际目录、会话数与最近活动；长名称与长路径单行省略并可悬停／聚焦查看全文，目录缺失时不显示占位。
- 默认排序按最近活动降序，同值与未使用工作区保持登记顺序；切到「手动排序」后与侧栏顺序一致。
- 搜索命中名称或目录，清空后恢复全部；无匹配与无工作区分别显示对应空状态。
- 点击「移除」先出现原生确认框；确认后该工作区从列表消失，原生侧栏与工作区选择器同步移除，会话仍在最近与搜索中，磁盘文件不变。
- 无效、未知或服务缺席时移除被拒绝并给出对应提示，不误删其他工作区。
- 加载失败显示页面错误并可重试，不显示为空列表。
