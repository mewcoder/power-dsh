# 插件更新

## 标识、入口与范围

功能 id `plugin-updates`。仅在 **设置 → PowerDSH → 通用** 的最后一行显示「插件版本」：左侧是与其他设置项相同的标题及当前运行版本 `x.y.z`，不重复产品名；右侧默认显示「检查更新」，确认可更新时替换为更新按钮，不并排显示两个入口。复用设置行的间距、分隔线、字体与公共按钮，右侧按钮使用 `md` 尺寸（36px，与通知下拉等高），不再使用跨分类页脚。该入口不设独立开关，配置 ready 后即在通用分类显示，不改变安装来源和已经交给市场的任务。功能不检查 DSH 宿主更新，不自动安装或定时检查新版。

## 配置与行为

用户主动检查时先核对本插件最新正式版；运行版本与正式版相同或更高时在版本号旁边以成功主题色的普通说明文字显示「无需更新」并直接返回，不加背景、阴影、圆角、内边距或加粗；右侧仍为可点击的「检查更新」按钮，不在版本号下新增结果行，不要求市场刷新远端元数据。更新日志链接与版本号放在同一行，不单独起一行，仅在窄面板空间不足时自然换行。确有新版时再发现同源 dsh-market 的公开 update API v1，要求正确 schema、检查／更新／进度能力和已核对的端点。本轮按市场 `1.73.19`、提交 `da774820fd49f4915461ff2031eedbef9b48dfe7` 的 `UPDATE-API-V1.md`、`routes.ts`、`update-api-v1.ts` 实现；该 API 当前为 beta，缺席、旧版、鉴权失败或结构改变都明确提示通过插件市场处理，不调用旧版私有 mutation。

只查询 `power-dsh`。正式版本由 owner-only `readPluginRelease` 读取：Host 经已核对的 subprocess 执行固定仓库的 `git ls-remote --tags`，解析普通／annotated tag 及 peeled commit；再匿名 HEAD 查询 GitHub 的公开 `/releases/latest` 与该版本固定附件 `power-dsh.tgz`，只接受正式版本标签和官方 HTTPS 附件跳转。不调用 GitHub REST API，也不把最新 Git 提交或尚未发布的标签当成正式版。Git 命令禁用交互与凭据助手，不读写用户 Git 配置，不 clone、checkout 或修改仓库；当前 Host 没有 Git 时明确提示，不新增运行依赖或自动安装 Git。

市场的 Git 来源版本可能是提交号，须核对市场目标提交等于正式 Release 标签解析后的提交，才能显示「更新到 x.y.z」。归档路径的版本须与正式 Release 版本一致；local／linked／generation 可以只读比较当前正式版本，但不在此处转换来源或提供安装。没有可靠目标显示「未确认可用更新」，不能把读取失败或未知版本说成已最新。

有新版时显示目标版本、官方 Release 更新日志链接和「更新」按钮。点击打开宿主公共 Modal，显示当前 → 目标版本及可能需要刷新／重启的说明；取消不写入。确认时重新检查目标和安装基线，变化则要求重新检查，不静默接受另一个版本。POST 只发送固定包名，市场持有安装、兼容检查与恢复；本插件不停止自己、不执行 pnpm、不写 profile manifest、patch 或文件，不绕过市场发布等待和运行中任务保护。

市场接受后按 operationId 查询其公开进度，只有返回成功且安装版本达到已确认目标，才显示已安装。确认后的目标复核、安装与读回过程只显示禁用的「正在更新…」，不并排提供检查或再次更新，不编造下载百分比。已提交而结果未知时仅提供「重新查询进度」，不重复安装；普通检查失败仍可检查重试。

安装成功后右侧只保留一个后续动作：需要重启时优先显示「重启应用」；仅需要刷新时显示「刷新界面」。两者都需要时只重启。重启只提供给已核对能力的本机 macOS／Windows 打包桌面端；普通 Web、远程 Host 或能力缺席时显示简短手动重启说明，不把刷新当作完整重启。更新后的重启不受侧栏 `showRestartButton` 显隐开关限制，复用重启模块的 owner-only 请求、同一路径校验、助手交接和忙状态。点击先用原生 Modal 确认，Windows 明确强制关闭及任务中断；取消、离页、失权、目标或连接代际变化后的旧回调不执行。重复点击只提交一次，失败保留安装结果并通过共享错误反馈允许再次确认，不自动重启。

版本说明保留当前运行版本及已安装目标；「已安装，重启后生效」与「已安装，刷新后生效」使用普通成功色文字。完成凭据只保存目标、原运行版本和生效要求，使用按页面路径隔离的本地存储，不保存配置、日志或认证信息；安装成功后立即保存、再清除待处理记录，避免重载丢失。重开页面时仅恢复已记录的成功结果，不查询新版或再次安装；只有当前 Client 与 Host 运行版本均达到目标才清除凭据并显示「无需更新」。Host 未升级或核验失败保留待生效提示。没有可靠运行版本证据时不把文件已安装当成新版已生效。存储失败保留本次内存结果并提示去市场核对。失败、取消、回滚、记录丢失和无法确认完成分别显示，保留可恢复状态，不自动重发 mutation。

## 生命周期、权限与兼容

常态不发网络请求；仅用户检查或恢复本页面已记录的更新任务时请求。市场发现与更新请求走当前页面同源、保留代理路径前缀、携带原生会话 cookie、禁止重定向。GitHub 公开 HEAD 请求在 Host 中匿名执行，只读取受限跳转元数据，不下载附件或携带 cookie。页面只在通用分类可见、配置 ready 且 writable 时允许检查与更新。切换到其他分类、关闭页面时取消本页面的读取与进度定时器、撤销未确认的弹窗及其旧回调、忽略迟到结果；已经发出的只读 Host 查询最多二十秒，Host 卸载则取消进程和网络请求，不影响市场持有的安装。返回通用时仅按原规则恢复已接受的更新任务，不自动检查新版。已接受 operationId、确认版本和市场 bootId 仅暂存在当前标签页 sessionStorage，并按页面路径隔离；重新打开时校验同一 Host bootId 后继续读回，不以旧记录操控新 Host。存储失败不撤回已经接受的任务，提示到市场确认。

错误使用共享反馈与固定双语文案，保留检查结果；行内仅展示简短摘要与「详情」入口，诊断在宿主公共 Modal 中查看和复制，不撑开设置行。检查失败由右侧「检查更新」重试，不再添加重复按钮；仅已有更新任务的进度读取允许单独重试，不重发安装。不显示原始 HTTP 响应、路径、配置或进程输出。不会因超时自动重试更新。未知或更高版本、开发版本不提供降级；不提供自建下载器或替代重启机制。Inspect 本轮不可用，宿主依据为已核对 `0.2.2-rc.1` 同源转发、公共 Button／Modal、configForms、subprocess 的托管生命周期与 `collected.stdout.readFrom(0)` 契约；不引入私有安装接口或生产依赖。

公开页面的 429 或具有明确限流响应头的 403 显示「接口请求过于频繁，请稍后重试」，按 `Retry-After` 等待，无明确时间时至少等待一分钟；Host 保留等待截止时间，并在当前标签页保存冷却，手动重查和重新加载均不在冷却内重新请求 GitHub，不安排自动重试。普通 GitHub 失败不误导为 DSH 登录或管理权限错误；只有同源市场鉴权失败使用权限提示。限流或缺少 Git 时提供公开发布页链接。正常启动及打开设置仍为零更新检查请求，无需新增「自动检查」开关。

Host 查询失败通过严格 DTO 保留固定阶段、原因、发生时间及可用的 HTTP 状态、Git 退出码、耗时和白名单网络／证书错误码。Client 通过共享诊断字段显示阶段与原因的双语解释、运行插件版本、当前阶段和恢复建议；市场请求区分网络、超时、HTTP、协议与状态核验失败，后续恢复成功清除旧诊断。没有收到详细证据时明确标记缺失，不把原始 stderr、路径、URL、凭据、响应正文或异常对象传给界面。该诊断是当前错误的状态，不新增日志中心或后台采集。

## 验收条件与验证

测试覆盖默认零请求、只读、Git 缺席、标签解析、正式 Release／附件校验、当前版与新版、重复点击、确认与取消、目标变化、市场 API 缺席／错误、限流等待、任务进度与实际版本、刷新／重启提示、sessionStorage 恢复和 Host 变化、卸载及迟到响应。静态检查和内存测试不等于真实插件自更新验收；本轮本地安装与页面结果另记兼容性记录，不执行真实在线升级或自动发布。
