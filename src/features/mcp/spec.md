# MCP 管理

模块 id：`mcp`；主开关 `mcpManagerEnabled` 默认 `false`。模块的[定义](definition.ts)、[配置](config.ts)、[Client](client.ts)与[行为测试](tests/)在本目录维护。

## 入口与范围

在 **设置 → PowerDSH → 增强** 打开「MCP 管理」，原生设置侧栏新增独立「MCP」页。入口默认关闭并独立持久化；关闭入口只移除页面。页面只管理全局 MCP，读取原生配置与已有提供插件的全局实例，不提供项目范围、项目文件扫描或项目实例展示，不建立连接或接管服务器生命周期。

列表按「用户／内置」分组：用户配置的 profile 条目及原生管理器配置项归用户；Bundle 声明、插件注册及模式提供的条目归内置。内置表示随提供方带入，不代表官方。原生用户自定义模式通过真实的 preset 配置 ID 对应 Loader 条目，不凭模式名称或 entryId 前缀推断归属。同一 Bundle 重复声明相同条目时合并来源；多个启用 Bundle 声明同一 MCP 或模式条目时，保留单个实际条目及内置分类，省略无法唯一确认的 Bundle 来源，不因来源歧义取消整个目录。启停权限仍只依据原生清单的唯一 patchId、状态和只读原因，不从来源标签推导写入目标。

`dsh-mcp-resources` 是共享服务，不作为 MCP 服务器条目展示。没有可确认全局作用域的动态实例不加入列表；页面不声称穷尽第三方自建协议桥或所有运行中连接。不增加服务器新增、编辑、删除、导入、连接测试、单个工具开关或会话覆盖。

## 原生目录与启停

[MCP 策略](mcp-policy.ts)使用 `pluginManager.listPlugins()`、`listBundles()` 和 `agentPresets.compositionInventory()` 取得原生配置清单。只有状态明确、有唯一 patchId 且没有 readOnlyReason 的 profile 条目可调用 `setPluginEnabled(entryId, enabled)`。模式组合中的相对 ID 和页面生成的 ID 都不能作为 profile 写入目标。

[提供方目录](mcp-providers.ts)从宿主 Loader 导入同一份 MCP 与 scope 模块，以 `registry.get(nativeMcp).fibers` 的真实回调身份取得已加载的全局实例。只读取必要的名称、生命周期标识、传输类型标量和作用域元数据，不按插件名包含关系或 `mcp__` 工具名称合成服务器，不枚举工作区或 Agent 以判断项目归属，不重新挂载或释放提供方实例。

静态配置与运行实例按 Loader 条目的实际 Fiber uid 对应，同一实例仅显示一次；不能依赖 Fiber 继承的 `entry` 或对象引用来去重，否则 Include 节点会造成重复条目。显示名称优先使用已解析配置中的 `serverName`；首次解析尚未完成时，只从公开 `rawConfig.serverName` 取字面量身份，不执行表达式，也不据此判断连接成功。模式归属 id 可从已验证配置回退读取。旧 Cordis 在等待依赖时没有公开的未解析配置入口：profile 声明仍可显示名称和 pending 状态，缺少公开身份的纯动态实例等到配置解析后再列出，不读取内部 `_config`。持久化操作仍使用原生 entryId。来源只显示可确认的 Bundle、提供插件或模式身份，排除 `cordis:include` 等结构节点，不编造配置路径或服务器简介。

若运行时提供 `mcpManager`，必须先由唯一匹配的 active `@deepseek-ai/dsh-mcp-manager` Loader 条目确认原生归属，再读取其 `list()` 与公开 `config.servers`：配置项归用户，插件注册项归内置，移除后的清理残留不作为新配置展示。第三方可能使用同名服务但提供不同协议（已核对 `dsh-skill-mcp-panel@2.3.7`）；没有可确认的原生归属时不读取其配置或调用其方法，继续按原生 profile、模式和动态 MCP 客户端实例列目录，不将同名第三方网关误认作原生管理器。已确认的原生管理器读取失败仍报错，不吞为空列表。配置项通过原生 Settings 的 descriptor namespace、revision 和单路径 `mutate` 修改 `servers.<name>.enabled`，不重写整份服务器配置。服务的 `ctx` 会被 Cordis 绑定为调用位置，因此真实管理器归属以原生 Loader 条目确定，不能用 `service.ctx.fiber` 推断。

动态插件没有通用的持久化启停接口时显示「由提供插件管理」并保持只读，不通过直接 dispose Fiber 假装保存了启停。原生管理器缺少可确认的 Settings 控制入口时同样只读。条件状态不显示为确定的开或关。

每次 profile 变更后重新读取原生状态：只有 application=applied、无警告且实际 enabled 与请求相同才算完成。需要重启、被覆盖、应用失败或读回不确定分别显示固定说明。原生调用抛错也会读回事实，不假设已回滚。同值请求不重复写入。管理器配置写入使用原生 revision 检查并核对实际 enabled，不重述其他字段或凭据。

开关表示配置启用意图，运行状态表示对应插件实际处于哪个生命周期阶段，两者分别展示。`runtimeState` 使用 `pending`、`loading`、`active`、`failed`、`unloading`、`inactive`、`disabled`、`unknown` 八个值：`active/failed/inactive` 显示「运行中」「加载失败」「未运行」三种稳定状态；`pending/loading/unloading` 只显示公共原生 `StateDot` 的 `ongoing` 加载指示，保留对应的双语无障碍状态名称，不常驻过渡文字；开关明确关闭时，第二行状态位置统一显示灰色 `idle` 圆点与「已关闭」／`Disabled`，优先于尚未完成卸载的运行状态；原生 `disabled` 同样显示「已关闭」。`unknown` 没有可靠运行数据时不伪造状态。状态来自可确认的 Loader/Fiber 或原生管理器归属，不按工具数量、保存成功或开关值猜测是否运行。Fiber active 也不等于网络连接成功，页面不标「在线」或「已连接」。全局停用可能影响同配置下的会话和在途调用；关闭 stdio 客户端可能结束子进程，关闭 HTTP 客户端不代表停止远端服务。已发生的外部操作不会撤回。

## 界面与数据

页面加载错误放在标题之后、搜索之前，卡片操作错误留在对应控件旁；复用[统一错误反馈](../../../docs/error-handling.md)，提供安全错误信息与复制，既有分环节代码继续保留，不自动重放启停操作。

页面沿用技能页的 760px 最大宽度、18px／600 标题、13px 说明、36px 搜索框和双列卡片，小于等于 520px 容器时单列。搜索框通栏，不显示范围 Tab 或项目下拉。用户组默认展开、内置组默认收起；搜索自动展开命中组，清空后恢复手动状态。卡片第一行仅显示带原生 Tooltip 的名称 span 与独立紧凑开关，名称允许键盘聚焦。三种稳定状态的文字前显示原生小圆点：运行中为绿色 `done`、加载失败为红色 `error`、未运行为灰色 `idle`，点与文字相隔 6px。稳定状态使用次要文字，加载失败使用错误 token；过渡阶段只显示原生小加载指示，并提供无障碍名称，不仅依靠颜色。标题下的第二行并排显示类型标签和运行状态，间距 8px，窄卡允许自然换行：原生 `stdio` 显示「本地」／`Local`，`streamable-http` 显示 `HTTP`；未知类型只省略标签，不默认推断本地。只要类型或状态可显示就保留信息行，两者均无内容时省略整行。标签沿用原生 outline 胶囊规格。「已关闭」与「运行中」共用第二行类型标签旁的状态位置，关闭使用灰色 `idle` 圆点。第三行保留工具缺省文字：配置状态明确且开关关闭时显示静态「暂无可用工具」／`No available tools`；开启但没有工具时显示静态「暂无已加载工具」／`No loaded tools`。两种缺省行均沿用工具入口的最小高度和间距。这两种状态均不显示箭头或工具区，卡片头部不可展开，也不显示可点击的悬浮或按下反馈；关闭前已展开的卡片立即收起，后台仍有工具或运行状态尚未停用时同样处理。重新开启且有工具后恢复本页原有展开偏好。有工具且未关闭时，第三行提供独立展开按钮，左侧摘要为「{count} 个工具」／`{count} tools`（英文单数为 `1 tool`），右侧为箭头，数量不加括号，默认收起。悬浮时整个卡片头部使用原生 hover 背景，展开后保持高亮和展开描边，工具行自身保持透明。按下和键盘焦点反馈覆盖头部，触屏不锁存 hover。展开后在带原生主题分隔线、模块背景及 `10px 14px 12px` 内边距的底部区域逐项显示完整工具名，长名称换行，不再截断或通过工具列表 Tooltip 展示；工具列表刷新为空时收起工具区，回到静态缺省行。三行头部的名称、类型、状态和空白区域都可点击展开或收起；工具按钮保留原生 Enter／空格操作。头部过滤开关及其他交互控件冒泡的点击，避免按钮双重切换或开关操作触发展开；开关不嵌套在展开按钮内。展开后的工具区在头部之外，点击、选择和复制工具文本不会收起卡片。每张卡片按原生实例 id 独立保留本页的手动展开状态，搜索、刷新及分组折叠不重置，离开页面不持久化。搜索同时匹配工具名和本地／HTTP 类型文案，但不自动展开卡片，多个工具仍属于同一张服务器卡片；只读原因、未知状态和操作错误关联对应控件。具体几何见 [UI 规范](../../../docs/ui.md#技能与-mcp-管理列表)。

owner-only RPC 为 `listMcpServers()` 与 `setMcpServerEnabled(id, enabled)`，共用 Mod 操作队列。响应为 `{ complete, servers }`，不含 scope、cwd 或 workspaces。服务器只返回白名单字段：id、名称、真实来源、用户／内置分组、enabled、配置状态是否明确、`runtimeState`、`transport`（仅 `stdio/streamable-http/unknown`）、能否操作、安全原因代码及 `tools: string[]`。类型只读取原生配置中已确认的传输标量，未知时省略标签，不从名称、工具、命令或 URL 推断；配置内容仍不进入响应。工具名优先读取原生 `tools.definitions(scope)`；旧版没有该接口时，从公开 `tools.schemas(scope)` 只提取名称，再通过 `tools.get(name, scope)` 与父作用域真实定义的对象身份比较，排除继承工具并保留当前作用域的同名覆盖。两条路径均遵守宿主作用域与限制，只对应已确认服务器的 MCP 命名空间，不额外调用 MCP 的 `listTools`。旧宿主投影 schema 时会读取当前作用域所有可见工具的描述与参数，Mod 不保存或返回这些字段；执行回调不读取、不调用。投影抛错时报告加载失败，不吞为零工具。响应仅传显示所需的注册短名，不传完整工具定义、描述、参数或回调。来源元数据继续用于分类和搜索，不作为卡片底部标签。不传 command/args、env、headers、URL、原始配置或原始诊断。Host 与 Client 均校验白名单；过期响应不得覆盖新结果，写入期间拒绝重复操作，失败后重新读取实际状态。

加载失败按初始化、插件清单、Bundle 清单、模式清单、运行实例/工具、条目元数据六个环节返回固定错误键，页面提供双语说明和对应的 `MCP-INIT/PLUGINS/BUNDLES/PRESETS/PROVIDERS/METADATA` 标识及重试入口。卸载或代际失效仍报告不可用。未知 RPC、网络及响应校验错误保留通用加载失败提示；所有提示不包含原始异常、路径、配置或凭据，失败不表示未配置或零工具。

页面挂载、窗口重新获得焦点及写入后读回时刷新列表。页面打开期间，每 2 秒在页面可见且没有读取或写入进行时刷新运行状态；隐藏时跳过轮询，卸载时释放定时器和监听。状态刷新不重置搜索、分组与卡片展开状态。

## 接口依据与验证

接口依据为 DSH `0.2.2-rc.1` 安装包及[历史标签核对](../../../docs/compatibility-audit.md#官方发行标签的接口证据)，覆盖 MCP 客户端、Scope、Cordis Registry／Fiber、Loader、Plugin Manager、Settings 及模式清单。上游源码的 `mcpManager` 与目标发行包是否实际提供该服务分别判断，不把新版字段或导出套到旧发行包。市场参考的确切提交、MIT 许可与边界见[来源研究](../../../docs/third-party-notices.md#技能与-mcp-来源研究)及[运行状态参考](../../../docs/third-party-notices.md#mcp-运行状态参考)，未复制第三方目录扫描器、独立连接器或 profile 接管逻辑。

[策略测试](tests/mcp-policy.test.mjs)、[提供方测试](tests/mcp-providers.test.mjs)和 [Host 装配测试](../../../tests/integration/host-wiring.test.mjs)覆盖真实 Cordis 作用域、模块身份、静态／动态去重、原生 Settings 更新、失败读回、白名单和卸载边界；原生 MCP 传输在测试中替换为不连接的插件。Client 测试覆盖仅全局的分组与搜索、卡片独立展开与折叠、工具完整展示和双语空态、开关与展开相互独立、运行状态标签及其与启用意图的区分、可见时空闲轮询与卸载清理、慢请求、过期响应、只读和错误恢复。仓库检查不代表实际远端连接或 GUI 已验收，不为测试而擅自启停用户真实 MCP。
