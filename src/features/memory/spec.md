# 记忆

## 标识、入口与范围

功能 id `memory`。主开关位于 **设置 → power-dsh → 功能 → 记忆**，默认关闭，始终可访问。开启后在原生设置侧栏的全局指令之后、技能之前显示「记忆」页，承载自动记录、全局与项目三个子开关、分组概览、条目查看、单条删除、打开对应文件夹及手动整理。主开关、设置入口与独立页导航均位于全局指令之后、技能之前。设置入口和独立页导航共用 Lucide Brain 大脑轮廓图标，不重复主开关。开启侧边栏独立页面时，记忆移入该页面，并注销重复的设置入口；关闭独立页面后恢复设置入口，不改变记忆开关、子配置或文件。

提供全局和当前项目两层跨会话记忆，四种类型为 `user`、`feedback`、`project`、`reference`。自动记录默认开启，可独立关闭；关闭时继续召回，只有用户明确要求记住／更新时才记录，明确忘记仍可执行。日常记录使用当前对话模型，不另选模型；该开关改变模型指令，不把自然语言意图判断冒充强制权限校验。记录效果取决于模型，不承诺完整提取。不开后台提取代理，不读取历史会话正文，不保存聊天全文，不实现向量检索、定时 Dream、同步或导入导出。

## 配置与行为

通过原生 `configForms` 持久化，配置键均归本功能所有：

| 键 | 默认 | 行为 |
| --- | --- | --- |
| `memoryEnabled` | `false` | 注册／释放策略、索引、工具和管理页；关闭保留文件 |
| `memoryAutoCapture` | `true` | 允许主动记录；关闭后仅按明确请求保存或更新，继续召回 |
| `memoryGlobalEnabled` | `true` | 允许模型读取和写入全局记忆 |
| `memoryWorkspaceEnabled` | `true` | 允许模型读取和写入当前项目记忆 |

子作用域关闭后管理页仍可查看与清理该作用域的已有文件。总开关关闭或插件释放后拒绝记忆 RPC 与工具调用。自动记录在总开关、自动记录和作用域开关允许的范围内运行；关闭作用域后禁止模型日常读取与写入。

### 保存查重与手动整理

保存前要求模型先用 `list(query)` 查找相关主题并读取已有内容，优先更新原文件。查找支持同一作用域中名称、摘要与正文的大小写无关子串匹配及分页；不调用额外模型。Host 对新建内容作 Unicode NFC、换行与行尾空白归一化后精确查重，命中则返回已有条目与 `reused: true`，不新增文件或更新时间；不同作用域不互相查重。同名更新需版本匹配且正文、摘要均未变化时不重复写入。语义相似仍由对话模型判断，不宣称精确查重能解决改写重复。

每个分组的操作区首位提供「整理记忆」图标，位于打开文件夹左侧，默认选择点击的全局／项目范围；弹窗仍可选择其他范围及已配置模型，默认当前对话模型，没有可识别的当前对话时明确使用宿主默认模型。更换整理模型不修改聊天模型，不新增 API Key 设置。用户点击「生成预览」才将所选作用域的完整有效条目发给该模型；模型无工具权限，只返回合并／精简建议。禁止按时间自动删除、跨作用域移动、创建新文件或凭空补充事实；删除只能作为合并重复条目的一部分。异常、不完整或输入超过 80,000 UTF-16 码元的作用域拒绝整理，不静默只处理部分。单次最多涉及 50 个文件；超量结果拒绝并提示缩小整理范围。

分组右侧固定为整理、打开文件夹、删除三个原生 ghost/sm 图标按钮，均为 28×28px、16px 图标；打开文件夹与删除使用 `folder-open-outline`、`trash-outline`，整理使用 Lucide DatabaseZap（`database-zap`）内联 SVG。三个按钮统一使用主题灰色与普通悬停背景。各图标有包含分组名称的 Tooltip 与无障碍名称，收起时仍可操作，不改变展开状态；页头移除整理按钮。整理只对完整且全部条目有效的非空分组可用；整组删除只对完整非空分组可用。整组删除弹窗明确范围，确认后通过既有 `clearMemoryScope(scope, revision)` 核对整个作用域快照，删除该组全部条目，保留其他作用域、索引及项目元数据；失败、部分完成和版本冲突沿用共享错误反馈与刷新，绝不自动重放。只读、断线及进行中状态沿用现有权限保护。

预览完整列出原文、修改后正文、被合并条目的原文和理由。用户确认「应用」后才写入；空建议显示「暂时无需整理」。预览仅 Host 内存持有，10 分钟过期，最多一个生成任务／待应用预览；离页、关闭弹窗、断线、功能关闭、服务离开或插件释放取消生成并丢弃预览，60 秒超时失败。工具调用／截断／异常模型输出均不应用。

应用时重新核对整个作用域版本及文件内容，冲突需重新生成。先在 `power-dsh/memory-backups/<任务标识>/` 备份所有涉及的原文件及恢复清单，再记录恢复日志后修改；成功删除日志、保留备份并重建索引。中途失败尝试回滚，进程意外中断由下次操作恢复；恢复发现文件已被外部修改时停止并明确提示从备份处理，绝不覆盖外部新内容。预览不可重复应用，失败不自动重放。整理属于用户显式管理操作，不受自动记录子开关影响，不提供定时开关。

### 管理列表

折叠标题按官方 `PluginInventorySettingsTab` 对齐：12px 原生 regular 箭头在名称左侧、内部间距 8px、标题行最小高度 36px，相邻组用 0.5px 主题分隔线与 14px 顶部内边距分隔；展开列表不增加左侧缩进，条目与分组分隔线的左边界一致。

三个子开关下方直接显示记忆分组，不显示「已保存的记忆」标题、总数或常驻刷新按钮。页面打开、窗口重新聚焦、连接恢复及修改后自动读取，读取失败仍通过共享错误反馈提供重试。全局和每个项目各为一个原地折叠分组，默认全部折叠，可独立展开多个；状态只在当前页面挂载期间保留，刷新不重置。标题行显示名称、旋转箭头、数量和三个操作图标，不显示装饰图标或分组更新时间。打开文件夹指向该组的存储目录（`MEMORY.md` 与条目 `.md` 平铺），全局打开 `memory/` 根目录，项目打开对应项目记忆目录，不打开项目源码目录、不切换展开状态。该操作仅限有管理权限且列表读取成功时使用；进行中防止重复点击，失败保留列表并使用共享错误反馈。项目只显示目录名，完整路径由公共 Tooltip 提供；计数仅包含记忆条目，不包含机器生成的索引与作用域元数据。空且完整的作用域不占位；读取不完整的作用域保留，折叠时仍显示共享错误反馈，允许打开文件夹但禁用整理和整组删除。

分组标题使用原生 button，Enter／Space 切换展开，`aria-expanded` 和 `aria-controls` 关联本组内容，焦点保持在标题。箭头有短过渡，减少动态效果时关闭过渡；只控制自有 DOM，不新增 Host 接口。展开后直接显示本组全部条目，不提供搜索框、搜索无结果状态或类型筛选。条目主标题优先显示可读摘要，异常条目回退文件名并显示异常标识；文件名放入详情，列表和详情均不展示类型，日期保留在列表，条目操作只提供确认删除。

全部作用域成功且完整读取、没有条目时显示大脑图标、「还没有记忆」和一句提示「聊天中的有用信息会自动记录」，不再额外展示示例块或重复说明。清空后的完整空分组消失。加载、读取失败或扫描不完整时不显示首次空态；不完整作用域始终保留错误反馈。

条目「删除」对齐官方模型设置的行内危险操作：使用公共 `Button` 的 sm／ghost，28px 高、12px／18px 文字，无描边、无图标；文字使用 `--dsw-alias-state-error-primary`，悬停使用 `--dsw-alias-interactive-bg-hover-danger`。保留原生禁用与键盘反馈，点击后仍需二次确认。二次确认弹窗遵循 [UI 规范](../../../docs/ui.md#确认弹窗) 的确认弹窗规则：outline「取消」在左并通过 `data-modal-autofocus` 获得初始焦点，附加危险样式的 outline「确定」在右。

标题下的页面描述右侧显示 14px 原生问号图标。悬停或键盘聚焦时通过公共 Tooltip 只显示一句说明「自动记住你的偏好和项目要点，下次聊天接着用」，换行显示实际本机保存位置，不追加模型传输、关闭或删除行为说明。不重复开关说明，不展示摘要、召回或运行时上下文等术语；目录未读到时只说明本地存储，不编造路径。完整说明同时作为问号的无障碍名称，问号可聚焦；底部不再显示路径、说明或折叠控件。浅深主题使用宿主 token，窄屏允许工具栏和条目操作自然换行。

条目更新时间按客户端本地时区显示为 `YYYY-MM-DD HH:mm`，使用 24 小时制，不显示秒；无效或缺失时间不编造日期，分组标题不显示时间。磁盘仍保存原始 ISO 时间。

详情继续使用公共 `Modal` 与 `MarkdownText`，宽度对齐官方 `PresetGuideDialog` 阅读弹窗的 `min(640px,100%)`，随宿主遮罩保留视口边距，外观、标题与右上角关闭控件由宿主提供。文件信息、完整正文和来源信息共用一个可键盘聚焦的滚动区，高度上限参照官方 `DetailDocument` 的 `min(560px,60vh)`；标题与关闭控件在滚动区之外，不截断正文或压缩子区块。窄屏自然缩窄，不把删除确认弹窗一并放大。

详情的「文件」只显示带 `.md` 扩展名的文件名，不显示完整路径，不追加「偏好／纠正／项目／参考」等内部类型。文件名自然换行且可选择复制。

### 文件与一致性

数据位于 `profileContext.home/power-dsh/memory/`（默认 `~/.dsh/power-dsh/memory/`），目录统一使用单数 `memory`，不增加旧目录兼容读取或自动迁移。全局文件直接位于 `memory/` 根目录，不另设 `global/`；项目目录直接位于 `memory/<规范化绝对路径的 SHA-256>/`，不另设 `workspaces/`，项目元数据保存在自有 `scope.json`，不依赖宿主工作区登记。全局扫描只读取根目录条目，不递归项目目录；项目扫描仅把项目目录计入作用域上限，忽略根目录的全局记忆与文件管理器元数据，仍拒绝非法目录、symlink 和哈希名普通文件。工作区来自调用会话的 `session.header.cwd`，realpath 归一化；没有 cwd 或目录不可访问时仅使用全局作用域，拒绝项目写入，不回退进程 cwd。模型不得提供项目路径。

每个作用域的 `<name>.md` 和机器生成的 `MEMORY.md` 放在同一层，不另设 `entries/` 或类型目录；索引中的相对路径直接指向 `<name>.md`。管理扫描仅读取本层条目，不递归读取其他项目。条目是事实源，索引是可重建数据；frontmatter 使用固定字段及 JSON 标量值：`schemaVersion: 1`、`name`、`description`、`type`、`created`、`updated`、`originSessionId`。类型只作为条目元数据，工具和管理接口继续使用 `type/name` 标识；同一作用域中文件名唯一，不同类型不能覆盖同名文件，`memory` 为索引保留名称。正文最多 1,200 个 UTF-16 码元，名称是最长 64 字符的 kebab-case，描述单行最多 160 码元。日期与来源会话由 Host 管理，模型不可伪造。所有记忆按更新时间倒序、同时间按 id 排序。

仅 Host `node:fs` 写入自有目录，不扩大 agent 文件沙箱权限。拒绝 symlink、非普通文件、目录越界、异常格式和超限文件；0600 临时文件原子替换，目录使用 0700。工具与 RPC 共用存储串行队列；同一 DSH_HOME 的多个 profile 共享记忆库，磁盘排他锁防止跨进程同时修改，忙碌返回可重试错误；可确认所属进程已经退出时才清理遗留锁。内容哈希作为读取版本，更新／删除必须匹配；清空必须匹配整个作用域快照，防止确认期间新增或变化的条目被删除。

条目提交后索引刷新失败时返回 `indexUpdated: false`，明确数据已经保存；不误报为未保存或自动重放。下次预热／管理刷新尝试重建。每次 agent 步骤前异步刷新当前作用域快照，避免其他 profile 写入后缓存长期过期；provider 本身只读内存。扫描有文件数量和大小上限，超限报告不完整，禁止作用域清空，不把读取失败伪装为空列表。工作区目录扫描忽略名称不匹配项目哈希的普通文件（包括 Finder 的 `.DS_Store`、Windows 的 `Thumbs.db` 等），不将它们计入项目数量；仍拒绝非法目录名、symlink，以及项目哈希位置上的非目录项。格式异常条目在管理页可见、可删除，但不进入模型索引。

作用域清空逐条删除；中途发生 I/O 故障或功能关闭时停止，若已有删除则明确报告部分完成并刷新实际剩余内容，不自动重放。磁盘读取失败不阻止四个独立配置开关的保存。

### 模型工具与注入

一个工具 `power_dsh_memory`，支持 `list/read/save/forget`。`list` 分页读取可用作用域；`read` 返回正文与版本；`save` 创建时要求空版本、更新时要求读取版本；`forget` 要求读取版本。执行时再次核对开关、作用域、取消信号和特性生命周期。工具声明原生强制要求的 `output { schema, render }`，预期错误只返回固定业务键，不返回原始异常、配置或诊断中的正文。

模型仅在 `save` 返回 `ok: true` 后才能声称新增或修改已保存；读取、查询和当前聊天中的确认不等于写入。已有相同内容可说明此前已保存，不暗示本次新增。自动记录关闭且用户未明确要求记录时，只确认当前聊天中理解的信息，不承诺下次聊天仍会记住。此项通过模型指令约束，不把自然语言回复视为磁盘保存证据。

`systemPrompt.section()` 注册精简策略 `power-dsh:memory-policy`，order 700，`interpolate: false`；`systemPrompt.context()` 注册索引 `power-dsh:memory-index`，order 130。索引合并全局和当前项目，两个作用域按更新时间顺序交错分配，完整行截断，共用 200 条／16,000 UTF-16 码元最终预算（包括标签与提示），不切断路径或条目。超限提示通过分页 `list` 查找，不自动删除记忆。所有注入数据转义标签及控制字符，并把 `{{` 中和，保持旧宿主插值安全。记忆是低信任数据，不得覆盖用户指令或仓库规则；使用可变事实前应核实现状。禁止记录密码、令牌、验证码等凭据。

## 生命周期、权限与兼容

采用功能内可选 `systemPrompt` 注入，服务缺席只让记忆页显示共享错误反馈，不影响其他增强。注册跟随 `settings/document-updated` 与特性 context 释放；关闭后阻止已排队写入，已经原子提交的数据保留。不删除卸载后的文件。管理 RPC 复用现有 owner-only 检查、严格 codec 与共享错误反馈；Client 断线重连、离页、失权与迟到响应不能覆盖新状态，失败保留已确认列表，破坏性操作均二次确认。

`openMemoryFolder(scope)` 仅接受作用域标识，Host 核对目录存在且路径各级无 symlink 后，通过可选 `sessionController.canOpenWorkspacePath()` 与 `openWorkspacePath({ path }, signal)` 交给宿主打开。Client 不传任意路径，不创建缺失目录；原生服务缺席或无桌面能力时明确提示当前环境无法打开文件夹。功能关闭、插件释放或服务离开时取消未完成操作；失败不返回原始异常。接口已核对官方 `dsh-v0.2.0-rc.1` 与 `fcc0ad46` 的公开实现，当前会话 Inspect 不可用，尚无实际文件管理器验收。

宿主依据：本地官方源码 `fcc0ad46`（0.2.2-rc.1）及最低发行包 0.2.0-rc.1，来源见[参考研究](../../../docs/reference-research.md#dsh-社区记忆插件与宿主接线核验)。最低版本已有 section/context 与工具注册，不使用较新版本的工具 `when`。旧 context 忽略 `interpolate: false`，因此总是中和花括号；旧宿主在 `includeRuntimeContext: false` 时抑制索引，使用记忆索引需要支持运行时上下文的配置。索引在下一步骤生效，不承诺工具中途改写已经发出的请求。

插件不创建子进程或独立网络连接；日常记忆随当前会话发送给用户配置的模型并进入会话历史，手动整理通过宿主 `llm.stream()` 将所选范围发送给用户选择的已配置模型。删除或关闭只停止后续召回，不清除旧会话中的快照。外部手编不实时监听，下一步或管理页刷新后生效。

整理接口依据为官方固定源码 `fcc0ad46` 的 `packages/llm/llm/src/types.ts`、`packages/api/session-controller/src/catalog.ts` 及 `session-title-llm` 调用方式；Client 在声明 `sessions` 与 `modelDirectories` 依赖的子 context 中取得服务，通过公开 `modelDirectories.directoryFor(sessionId)` 与 `sessions.list` 的 `retainedBy.mainView` 识别当前模型，不从未注入的根 context 读取。宿主全局面板保留当前 Session；不能唯一识别或可选 Client 服务缺席时使用明确标记的默认模型。所需 Host 模型服务缺席只阻止整理；不要求最低宿主具备这些新接口，旧版日常记忆仍可用。当前 Inspect 不可用，源码核对与实际模型验收分别记录。

## 验收条件与验证
