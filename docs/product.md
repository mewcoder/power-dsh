# 产品规范

## 定位

PowerDSH 是独立社区维护的 DSH（DeepSeek Harness）插件，技术包名为 `power-dsh`，设置显示名为 **PowerDSH**。

品牌文案为「优雅克制，专注实效。让你的 DSH 更顺手、更高效。」，英文为「Minimal, elegant, yet deeply powerful. Making your DSH effortless and efficient.」。README 首屏按用户提供的中英引用块展示。设置页说明固定为「DSH 增强插件」，英文为「A DSH enhancement plugin」。GitHub About 与插件元数据使用完整简介：中文「DSH 增强插件。优雅克制，专注实效。让你的 DSH 更顺手、更高效。」；英文「A DeepSeek Harness (DSH) enhancement plugin. Minimal, elegant, yet deeply powerful. Making your DSH effortless and efficient.」。市场卡片使用已确认简介：「DSH 增强插件，提供技能/MCP 管理、全局指令、任务通知等实用功能，支持按需精简内置功能。」具体功能作为支撑，精简开关与功能数量不作为核心定位。功能收录以实际需要为准。

优雅、克制、实用同时指导产品设计，沿用宿主组件、主题和使用习惯。每项能力应解决明确问题，并控制入口、配置与常驻信息的负担。

追求宿主质感意味着符合其设计语言和交互习惯；名称、文案与图标不暗示官方背书。具体功能和变化随版本记录，以[更新日志](../CHANGELOG.md)及对应 Release 为准，专项说明负责各自的行为边界。

README 面向使用者，保留稳定的产品定位、真实界面截图、当前功能清单、使用入口和更新链接。功能清单使用「分类 / 功能 / 描述」三列表格，始终反映当前代码，不逐项记录版本号。发版时通过 Git 标签保留对应代码与 README 快照，详细变化记录在更新日志与 Release。开发状态、测试命令、SDK 矩阵和发版流程放在维护文档中。截图使用实际运行界面并标注对应版本，控制展示宽度、保留原图清晰度；版本变化时按实际界面更新，不放占位或模拟截图。

## 入口与状态

- 功能开关统一放在 **设置 → PowerDSH**，设置入口与页面标题中英文均为「PowerDSH」，技术包名与设置命名空间保留 `power-dsh`，按「通用」「界面」「管理」「精简」「其他」顺序分类，默认通用，组内按使用频率和功能关联性排序，范围见 [分类 Tab](ui.md#分类-tab)；每项增强有独立、持久化开关，默认是否开启由明确需求决定。全局指令（功能 id `personalization`）按用户确认的结构：Mod 内只放开关，开启后在设置侧栏新增独立「全局指令」Tab，承载原生全局 `AGENTS.md` 编辑，关闭后只移除入口并保留文件，原生指令读取继续生效。
- 任务内操作使用对应原生扩展点。增加第二个常驻入口需要具体场景，避免设置、侧栏和输入框重复呈现同一操作。推理等级按钮位于官方模型座位右侧，是经确认的常驻例外，只提供档位切换，详见[推理等级选择器](../src/features/thinking-effort/spec.md)。
- 内部模块是代码组织方式，不要求拆成多个安装项。
- 关闭界面增强撤销对应 UI；精简开关开启时停用匹配目标，关闭时启用匹配目标，不记忆之前的启用状态。停用或卸载 Mod 不自动启用这些目标。
- 成功保持安静，错误给出可执行的恢复方式。界面呈现已接受的配置与实际结果，未知状态不伪装成功。

技能管理的入口与单项策略分别保存：管理开关只控制独立「技能」设置页；页面按全局和工作区组织，不显示模式选择。技能启停仅对对应 DSH 范围生效，工作区限制不影响其他工作区，不修改共享技能文件。以原生调用策略读回状态，不因只隐藏列表就判定停用；详见[技能管理](../src/features/skills/spec.md)。MCP 使用另一个独立设置入口，只展示全局服务器，按用户与内置分组，提供搜索与卡片中的启停操作。不提供工作区范围、工作区文件扫描或工作区实例展示。可管理项走原生持久化接口，无对应控制入口的条目保持只读，不维护平行服务器配置或把启用当作已连接，详见[MCP 管理](../src/features/mcp/spec.md)。

任务通知在「通用」中使用单个默认关闭的独立开关，提醒完成、出错、等待输入和请求审批。完成与出错仅在对应会话未处于眼前时提醒；等待输入与请求审批始终提醒。其下「通知声音」默认开启，可独立关闭；开启后下方展开第二行，显示默认「系统默认」的提示音下拉和小播放图标，选中本机 macOS 内置声音或 Windows 系统声音事件后自动试听，也可手动重听。关闭声音时隐藏下拉和播放图标、保留声音偏好。主通知关闭时隐藏全部声音配置并保留偏好，远程界面不触发服务器原生播放；声音开关与选择行各保留一句简短说明，选择行使用「选择系统提示音」；具体提示音可能在专注模式下响铃，行为边界保留在功能文档中。不增加常驻入口或独立设置页，详见[任务通知](../src/features/notifications/spec.md)。

[壁纸](../src/features/wallpaper/spec.md)的主开关「开启自定义壁纸」是 PowerDSH「界面」页的第一设置行，位于快捷推理等级切换前，分类 `interface`、排序 -1。「通用」及壁纸专页不重复主开关。开启后在原生设置左侧注册独立「壁纸」入口和图标，排序 50.5，位于 PowerDSH（50）之后、全局指令（51）之前；关闭移除入口、图标和媒体效果并保留选择、图片和调节值。没有 PowerDSH 内部壁纸 Tab。原生壁纸专页具有自身 Title／描述，Title／描述下直接放置缩略图单选，再显示可见度／模糊滑块，不重复同名字段标题。可选无壁纸、官网流动、大肥鱼和自定义；官网流动作为预制选项，没有独立开关或主页调节面板。选择无壁纸保留专页但不挂载媒体，界面首行主开关始终可访问。自定义图片的更换与移除收在卡片底部名称右侧，文件名与格式只作 Tooltip 提示，不在下方重复整行。预制选择立即保存，拖动调节保持预览／提交和取消规则。旧流动与旧自定义图片通过兼容读取延续，新用户首次启用明确保存无壁纸。旧[流动背景模块](../src/features/flowing-background/spec.md)仅保留五个隐藏配置键，无 UI、注册或副作用；背景侧栏底部快捷入口已撤销。所有媒体复用既有授权的底层结构适配，不扩大宿主表面修改范围。

具体布局、语言与交互标准见 [UI 规范](ui.md)，原生启停机制见[架构规范](architecture.md)。
