# 第三方网页搜索

模块 id：`web-search`；主开关 `webSearchEnabled` 默认 `false`，搜索列表 `webSearchChain` 与获取列表 `webFetchChain` 默认 `[]`。模块的[定义](definition.ts)、[配置](config.ts)、[后端适配](backends.ts)、[回退链](provider.ts)、[凭据状态](state.ts)、[Host](host.ts)、[Client](client.ts)与[行为测试](tests/)在本目录维护。

## 入口与范围

在 **设置 → power-dsh → 功能** 打开「第三方网页搜索」，原生设置侧栏新增独立「网页搜索与获取」页。入口默认关闭并独立持久化；关闭入口移除页面与后端注册，并恢复官方搜索开关对应的工具限制。

页头显示「网页搜索与获取」标题与一句描述「配置搜索与获取服务，拖动调整优先顺序」；两个区域只显示「网页搜索」「网页获取」，不附加「提供方」或重复说明。本机获取行显示「本机直接获取」与当前位次；测试失败显示简短的分类原因，详细诊断从共享入口查看。

按用户明确要求，本功能**只提供设置页入口**：不贡献 `pages`，不进入[侧边栏独立页面](../standalone-page/spec.md)的功能页集合，因此开启独立页面时本入口仍留在设置侧栏，与其他功能页的迁移行为不同。

开启后本模块向原生 `ctx.web` 注册自己的搜索（`power-dsh-search`）与抓取（`power-dsh-fetch`）provider。内置 `web_search` / `web_fetch` 工具不变，改变的是谁回答它们。每个 capability 只注册一个 provider，避免原生 seam 在多个可用 provider 且未显式选择时抛出 `WEB_PROVIDER_AMBIGUOUS`。

**两个 capability 都固定到本功能的 provider，且只有一种状态。** 开启后原生 `searchProvider` 固定为 `power-dsh-search`、`fetchProvider` 固定为 `power-dsh-fetch`。

抓取统一由 `power-dsh-fetch` 执行：默认先调用本机抓取，没有第三方实例时行为与原生 `http` 一致。

抓取区始终包含**「本机直接获取」行**（状态点 + 名称 + 当前位次），默认位于 #1，可与第三方实例一起拖动或通过 `Alt` + 上／下方向键排序。该行不可移除，没有密钥、额度、编辑或第三方测试入口；获取请求严格按页面顺序尝试，首个成功即停止。

本机抓取免费、可访问内网与本机地址、不执行 JavaScript，因此默认排第一；用户可以将第三方服务排在它之前。关闭功能时撤销两个固定，恢复 profile 本应有的组合值。

首版只收录**有官方免费额度**的后端，这也是本功能存在的理由——不代用户接入付费 API：

| 后端 | 搜索 | 抓取 | 免费额度 | 认证 |
| --- | --- | --- | --- | --- |
| Tavily | ✓ | ✓ | 1,000 credits/月 | API Key（`Authorization: Bearer`） |
| Firecrawl | ✓ | ✓ | 1,000 credits/月 | API Key（`Authorization: Bearer`） |
| TinyFish | ✓ | ✓ | Search/Fetch 在限速内免费 | API Key（`X-API-Key`） |
| Exa | ✓ | ✓ | 10 USD credits/月 | API Key（`x-api-key`） |

额度数字取自各家官方定价页，随供应商调整而变化；页面只显示额度量级，不作为可用性承诺。TinyFish 官方定价页与 API 参考页的限速口径不一致（30/min、500/hour 与 12,000/天），本模块按更严的口径理解，超额由供应商返回 402，链路转向下一个后端。

不包含：新工具注册、按会话选择后端、自定义 baseURL、付费后端、结果缓存、多 key 轮换、把后端结果写入会话日志。

Exa 使用普通 API Key，获取入口为官方 dashboard 的 API Keys 页。搜索调用 `POST https://api.exa.ai/search`，使用 `type: 'auto'`，最多 100 条结果并只请求 highlights 摘要（每条上限 800 字符），将 URL、标题、摘要和发布时间映射为原生来源，不请求额外的答案合成。网页获取调用 `POST https://api.exa.ai/contents`，一次仅提交目标 URL，正文最多请求 100,001 字符、交付 100,000 字符，超出时标记截断；沿用 Exa 默认缓存策略，不强制每次重新抓取。空结果、空正文与逐 URL 错误均视为失败，进入后续步骤；401／402／429 沿用现有诊断与回退。新服务加入两组各自的添加菜单，不自动加入或改变已有顺序与密钥。

Exa 官方余额接口 `GET /team-management/credits` 需要显式开启 Team Management 权限的管理密钥，普通搜索密钥不能默认读取。本功能不要求提升密钥权限、不调用该接口、不伪造固定的剩余额度；额度读取返回 `unsupported`，页面不显示无效的额度刷新行。每月免费额度以官方账户实际提供为准，不执行充值或支付。

## 配置与凭据

- `webSearchEnabled`：主开关，`volatile`，经原生 `configForms` 保存。
- `webSearchChain`：`{ id, provider }[]`，搜索链的提供方实例，顺序即回退顺序。`id` 是实例标识（也是凭据记录 id），`provider` 是服务商；同一服务商可出现多次，各自持有 key。
- `webFetchChain`：同样结构的抓取链，与搜索链完全独立；本机步骤以 `{ id: 'power-dsh-local-fetch', provider: 'local' }` 保存位置，不关联凭据。旧配置、空列表或缺少本机步骤时只在内存补到首位，读取不写配置；首次编辑抓取链时一并持久化。重复本机步骤只保留第一个，不允许通过排序、移除或密钥接口删除、复制、配置本机步骤或将其加入搜索链。

兼容旧版字符串数组（例如 `["tavily"]`）：Host 与 Client 序列化 schema 均接受旧格式，启动和读取不改写配置，不因旧条目让整个插件失效。读取时为搜索与获取分别生成不与现有实例冲突的稳定 id，继续使用原 `power-dsh/<提供方>` 凭据；同一旧提供方出现在两组时，两行仍分别显示。首次编辑某条链时，先将保留条目的旧密钥复制到各自实例记录，再通过原生 `configEditor` 只将该链保存为对象数组。直接替换或清除旧行密钥时先完成该链转换；清除后不再回落到旧密钥。复制或配置保存失败保留旧配置和原凭据；原记录不自动删除，避免影响另一条尚未转换的链。凭据库缺席时仍可读取旧列表，但需要复制密钥的转换操作明确失败。

**两条链完全独立。** 实例只属于一条链；加入、移除或调整其中一条不影响另一条。两个字段分开存储，写入只改被操作的那一个。
- 每个后端声明 `keyUrl`：该服务商创建 API Key 的页面。展开编辑后，在输入框上方与「API Key」标签同一行右侧显示「获取密钥」文字链接，不使用图标；已配置密钥时也保留。地址随目录下发，Client 不硬编码；外链在新页面打开并设置 `noopener noreferrer`，无障碍名称包含服务商和位次。
- API Key **不进入设置文档**：写入原生凭据库 `ctx.credentials` 的 `power-dsh/<backend>` 记录（`{ kind: 'api-key', key }`）。设置页只能读「已配置／未配置／不可写」，不回显明文；保存后清空输入框。空值提交即删除该记录。

选择被固定在原生 `web` Loader 条目的 `searchProvider` / `fetchProvider` 上，只写这两个字段，保留其余配置。关闭功能时只撤销仍等于本模块 id 的值，并恢复该条目在 profile 中本应有的组合值（`inherited`），不覆盖用户之后在原生页做出的选择。

## 行为

**启用顺序**：保存偏好 → 刷新各后端密钥 → 注册 provider → 固定原生选择 → 恢复原生搜索工具及解除搜索限制。即使「停用官方搜索」同时开启，也保留该偏好并允许已固定的第三方搜索使用原生 `web_search`；启动时修复旧版遗留的禁用声明。关闭时先按该偏好恢复工具限制，再撤销选择和注册。任一步失败都不视为启用成功；恢复工具失败会重新限制搜索、撤销选择并注销 provider，页面读取与写操作均返回失败，不能只报告提供方已配置。

**回退链**：搜索与抓取各走自己的链。按该链顺序遍历可用后端；某个后端抛错（含 401/403/429 额度与鉴权失败）就转向下一个，全部失败时抛出聚合错误，逐条带后端 id 与原因。搜索没有可用后端时 `available()` 返回 false，不借用抓取链；抓取只要本机或任一第三方步骤可用即返回 true。密钥在每次调用前从凭据库解析，改 key 或调顺序对下一次请求立即生效，无需重启或重注册。

**密钥缺失**：所有第三方后端均要求配置 API Key，不启用免密钥模式。未配置的实例在链路中被跳过，测试按钮禁用，Host 测试与后端也在发请求前拒绝空密钥。行头仅用状态圆点表示配置情况，悬停提示与无障碍名称显示「已配置／未配置」，不另加常驻文字标签，不回显密钥。本机直接获取仍不需要第三方密钥。

**额度与余额**：在此功能现有开关下，打开设置页后为已配置的实例按需读取，显示在行头下方的紧凑次要文字行，并提供「刷新」文字按钮。Tavily 使用 `GET https://api.tavily.com/usage`：有密钥上限时显示密钥已用／上限，否则显示账户套餐已用／上限，均为 null 时明确无上限；额外按量剩余额度单列，不把套餐耗尽冒充全部余额为零。Firecrawl 使用 `GET https://api.firecrawl.dev/v2/team/credit-usage` 的 `remainingCredits` 显示账户剩余积分，不用不含额外积分的 `planCredits` 倒算已用。TinyFish 使用 `GET https://agent.tinyfish.ai/v1/wallet` 的 `available_balance` 与 `currency` 显示 USD 钱包余额，保留负数与最多六位小数，不换算成免费搜索次数；组织钱包暂不支持时按真实拒绝访问反馈。

额度读取独立于目录加载、保存与搜索执行，不在插件启动时查询、不轮询、不根据额度自动调整调用链。查询仅使用已保存密钥，经 Host 执行并遵守宿主代理；15 秒超时，拒绝重定向，响应限 64 KiB。相同服务与相同密钥在两条链中共用 2 分钟内存缓存并合并并发请求，成功与失败均缓存；刷新与窗口重新聚焦遵循相同频率，按钮提示该规则。保存／清除密钥、移除实例及卸载时失效，迟到结果不能覆盖新凭据的状态。未配置的实例和本机行不查询、不显示额度；接口失败不伪造 0、不禁用编辑或搜索，复用行内共享错误反馈与脱敏诊断。额度 RPC 只传必要数值、固定枚举与安全诊断，不传原始接口对象、密钥、账号信息、自动充值配置或钱包链接。

**排序**：以拖动为主。整行可拖（仅在可写时），拖动中显示行半透明与落点插入线，落点按指针在目标行的上／下半决定插入其前或其后；松手时把整串新顺序一次提交，Host 校验提交集合与当前链一致，不一致则整次拒绝并返回 `webSearchOrderChanged`，不静默丢项。不提供上移／下移按钮；行可聚焦，`Alt` + 上／下方向键为键盘等价操作，说明放在视觉隐藏的可访问描述里。重排只写被操作的那条链。

**布局与添加**：按 DSH `0.2.2-rc.1` 原生「设置 → 模型」页核对，正文最大 720px，标题组与正文间距 24px；每个提供方实例一行卡片，点「编辑」在该行内展开灰色面板。同一时刻只展开一行；字段按标签及密钥获取文字链接、32px 密码输入框、状态说明排列；取消与保存成组靠右，提交中不可取消。凭据不可写时保留编辑面板并说明原因；保存失败保留草稿，输入框关联共享错误反馈。列表末尾是一个整行虚线「添加」按钮，公共 Menu 的自有根类显式占满行宽，点击后选择服务商并新增实例（同一服务商可重复添加），添加成功后自动展开新实例的编辑面板；失败不切换当前编辑行。搜索列表为空时直接显示添加入口，不额外显示空卡片。添加或移除失败分别在对应区域或行显示共享错误反馈；读取失败或网页服务不可用时禁止写入。具体尺寸见 [UI 规范](../../../docs/ui.md#网页搜索)。

编辑面板直接从「API Key」标签与「获取密钥」链接开始，不重复行头已有的服务商名称标题。

**测试**：每个提供方行头在「编辑」前显示 28×28px 测试按钮，使用自绘斜试管轮廓（24×24 画布、2px 描边，显示为 16px）、主题灰色与 ghost 悬停样式，不使用播放图标；Tooltip 与无障碍名称标明测试搜索／测试获取、提供方和位次。无需展开编辑，编辑面板不重复测试按钮。测试中显示原生小转圈并禁止再次测试；缺少必需密钥或页面不可用时禁用。成功与失败结果均在对应行头内、名称与操作组之间显示，不另起一行，收起编辑仍可见；成功显示结果数／字符数与耗时，失败沿用共享错误反馈并保留「详情」。窄屏允许行头自然换行。只测该链的能力——搜索链发一次真实小搜索（query `DeepSeek`，上限 5 条）；抓取链真实抓取一次 `https://example.com`。两者都消耗一次额度，使用已保存的密钥，不提交编辑草稿。

测试请求最多等待 30 秒，超时释放测试状态。失败摘要区分认证、拒绝访问、额度、限流、网络、超时与响应异常；详情保留服务商、搜索／获取、请求或 RPC 阶段、缺少密钥／已配置密钥状态、HTTP 状态、白名单网络／证书错误码、耗时及首次观察时间。不跨 RPC 传递异常原文、堆栈、URL、请求头、密钥或响应正文。Client 不得将 Host 已返回的原因替换成笼统「测试失败」；旧 Host 未提供诊断时明确说明需要重新加载，RPC 故障与第三方请求故障分开处理，不根据单一通用摘要猜测网络或额度原因。

成功和失败提示均在测试完成 5 秒后自动消失，运行中的测试不计时；再次测试重新计时，旧定时器不得清除新结果。与失败提示交互时停止自动消失，便于查看和复制详情；下一次测试替换该提示。卸载时清理定时器。

**抓取：默认本机优先，可调整顺序。** 抓取始终由 `power-dsh-fetch` 服务，按包含本机步骤的已保存顺序逐项尝试；没有第三方实例时只调用本机：

1. 默认先本机再第三方；用户将本机移到中间或末尾后，下一次请求立即采用该顺序。
2. 任一步失败后继续下一步，首个成功即停止；全部失败时汇总已尝试步骤的失败。
3. 请求被取消时不再尝试任何后续步骤，包括尚未执行的本机。
4. 本机抓取通过 `loader.import('@deepseek-ai/dsh-web-fetch-http')` 取得其公开 `HttpFetchProvider` 类，复用原生实现；URL 校验、同源重定向、大小与字符集限制都不在本功能里另写一份。该包缺失或结构不符时跳过本机步骤，保留其余步骤的相对顺序。

本机返回的 body 可能是 `html` 或 `text`，原样交给 seam，由宿主自行转换；第三方后端返回的已是抽取后的正文，以 `text` 交给 seam，因此不会二次走原生 HTML→Markdown 转换。

**并发**：Host 侧所有写操作与注册/固定走同一条串行队列；页面在写入期间禁用控件，旧代际响应不得覆盖新结果。

## 生命周期、权限与兼容

关闭开关、卸载模块或 `web` 服务被替换时注销两个 provider 并清空已解析的密钥槽；不自动删除已保存的 key 记录，用户可在页面移除。provider 注册随功能子 context 释放。

接口依据为 DSH `0.2.2-rc.1` 安装包的 `@deepseek-ai/dsh-web`（`registerSearchProvider` / `registerFetchProvider`、provider 的 `id/title/description/available/ready/search/fetch` 形状、`WebSearchResult` 与 `WebFetchBody`）、`@deepseek-ai/dsh-web-fetch-http`（`fetchProvider: 'http'` 的默认组合）与 `@deepseek-ai/dsh-credentials`（`modifyRecord` / `describeRecord` / `readRecord` / `deleteRecord`）。原生「插件 → 网页搜索」页通过 `web/listProviders` 列出已注册 provider，因此本模块的两项会以 `power-dsh` 出现在该页下拉中。

`web` 服务、`credentials` 服务或可编辑的 `web` 条目缺席时不注册、不改写配置，页面显示对应说明而不是伪造成功。

两个可选服务都必须经 `ctx.inject([...], child => …)` 取得，不能直接读取根 context 的属性：Cordis 对未在该 fiber `inject` 列表中声明的服务，属性读取会抛 `cannot get property "…" without inject`，那会让整个设置页读取失败。凭据服务不可用时页面降级为「未配置、不可写」；`web` 服务不可用时报告 `available: false` 并保持原生选择不变。

## 验收条件与验证

- 开启后 `ctx.web.listProviders()` 同时出现 `power-dsh-search` 与 `power-dsh-fetch`，`web` 条目的两个字段分别指向它们；抓取链空与非空时 provider 相同。
- 「停用官方搜索」与第三方功能同时开启时，偏好不变，活动全局及模式声明的 `search` 为 `true`，已有可用工具代际的 `web_search` 可执行；关闭第三方后恢复搜索限制，`web_fetch` 保持可用。原来没有搜索工具的旧会话需重新打开。
- 抓取链为空时，能由本机读取的 URL 仍成功返回（行为与原生 `http` 一致）。
- 本机步骤可移至首位、中间或末尾，刷新后顺序保留，实际失败回退与页面一致；本机缺席时跳过、请求取消时停止，重复或遗漏本机的排序被整体拒绝，旧链的密钥与搜索顺序不变。
- 关闭功能后两个 provider 都消失，`web` 条目的两个字段都回到组合值。
- 配两个后端时搜索成功（不出现 `WEB_PROVIDER_AMBIGUOUS`），顺序调整后请求先到靠前的后端。
- 只把某后端加入搜索链后，抓取链不变，且该后端不参与抓取；反之亦然。
- 首个后端返回 429 时自动落到下一个并成功返回结果。
- 所有第三方后端未配 key 时均被跳过，测试和直接后端调用也不发送空密钥请求；添加成功后自动展开新实例。

- 卸载后不再有本模块的 provider，`web_search` 回到原生组合。
