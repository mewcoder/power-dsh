# 技能管理

模块 id：`skills`；主开关 `skillManagerEnabled` 默认 `false`。模块的[定义](definition.ts)、[配置](config.ts)、[Client](client.ts)与[行为测试](tests/)在本目录维护。

## 入口与范围

在 **设置 → PowerDSH → 管理** 打开「技能管理」，原生设置侧栏新增独立「技能」页。入口开关默认关闭、独立持久化；只控制管理页的显示。关闭入口不会恢复已停用技能；停用或卸载整个 Mod 则释放它的运行时限制，技能回到提供方原有规则。重新加载 Mod 后恢复已保存的停用名单。

页面复刻原生内置插件布局：顶部范围说明、**全局／工作区／发现** Tab、搜索、折叠分组和双列技能卡片；窄容器单列。管理卡片右上角提供启停开关，不展开收起。各分组标题旁显示技能数量、不显示描述；不增加目录提示或感叹号。技能简介最多两行、悬停读全文，同一行卡片等高、底部操作对齐，外层滚动区预留稳定滚动槽，尺寸与主题见 [UI 规范](../../../docs/ui.md#技能与-mcp-管理列表)。全局按「用户」「内置」分组：运行时和 bundled 来源归内置，其他来源归用户，不设来源筛选。卡片底部左侧只显示实际目录简称，右侧为详情；发现卡片增加唯一的「导入」操作。用户默认展开，两类并存时内置默认收起，只有内置时默认展开。手动折叠优先，刷新不覆盖；搜索自动展开匹配组并显示匹配数量，清空后恢复。工作区逐项目独立折叠、搜索通栏，不设工作区下拉和模式选择。MCP 使用[独立管理页](../mcp/spec.md)。

分组描述移除后不保留空行或占位，标题和卡片之间仅使用共享分组的 10px 间距，不再给卡片列表叠加顶部外边距；全局、工作区与发现 Tab 保持一致。

页面加载与读取错误反馈放在 Tab 下方的列表内容区，搜索框存在时排在搜索之后，不插入标题说明与 Tab 之间。工作区和发现的分组反馈仍留在各自分组内。

- 全局目录调用原生 snapshot 时不传 cwd，原生 filesystem provider 因此只加入用户、自定义、内置等非工作区来源。不能先读取当前工作区的合并结果再过滤，否则工作区的同名技能会遮住用户副本。
- 工作区范围把 Host `workspaceRegistry.list()` 中每个已导入工作区各展示为一个可折叠分组（响应只投影 `{path,title}`）：标题为保存的项目名称，路径通过悬停区分同名项目，旁边显示技能数量，不显示描述。分组默认展开，允许手动收起及多组同时展开；进入工作区 Tab 后以各自 cwd 读取目录，折叠时仍显示已确认数量。重复折叠不重读，切换 Tab 和刷新保留手动选择，窗口 focus 只重读展开的项目。搜索跨项目并自动展开命中组，清空恢复原选择。首次加载或失败且无旧目录时不显示数量，有旧目录则保留数量；折叠时仍保留必要的加载、错误和不完整反馈，不能隐藏失败或冒充空列表。卡片启停与详情使用所属 cwd，失败只重读本组。读取完整且没有技能或搜索匹配的项目隐藏；整页无技能或无匹配时只显示一次空态。无工作区时显示「暂无已导入工作区」，不读取未登记目录。发现 Tab 同样逐项目独立操作，不合并项目；`workspaces` 是 Client 服务名，不能用于 Host 接线。
- 工作区根遵循原生 filesystem 语义：最近的 `.git` 所在祖先，否则使用所选 cwd。工作区子目录共享同一个工作区的限制；两个独立工作区互不影响。

## 来源元数据

来源保留目录简称（如 `.dsh`、`.agents`、`.codex`）与可确认的提供包身份，供 Host 元数据投影使用，不常驻卡片或详情弹窗。完整技能路径在详情弹窗显示，缺少文件路径时可使用公开的目录资源根。卡片简介最多两行，完整原文通过原生 `Tooltip` 显示，提示以 portal 呈现，避免被卡片裁剪，规则见 [UI 悬浮提示](../../../docs/ui.md#悬浮提示tooltip)。卡片右上角开关为 28×16px 小号尺寸，主题与交互沿用原生。

[来源解析](skill-origin.ts)直接使用 DSH 公共目录中的来源、文件路径及目录资源根。原生来源保留 `.dsh`、`.agents` 语义；其他提供方的文件技能从已有绝对路径中的 `.目录名/skills` 识别简称，不硬编码某个第三方插件的 source、接口或数据结构，不新增目录扫描。DSH 原生默认扫描 `.dsh`、`.agents`；当前 `.codex` 条目由已启用的第三方提供方注册进统一目录，Mod 只展示该目录的结果。内置来源使用已核对的 provider 对应关系，或公开路径中最近 `node_modules` 包的真实 manifest name。Office 的 `dsh-office` 和 Badge 的 `dsh-badge` 已按安装版 0.2.2-rc.1 源码核对；Office 资源根可以独立配置，因此不能假定其路径包含包名。未知来源不按技能名猜包名，不读取技能正文。来源字段 `origin` 是显示元数据，不改变分组、调用策略或读取范围；停用时保存，重载后保留。

## 只对 DSH 生效

**单项开关控制 DSH 的技能调用能力，不修改共享技能文件，不影响其他应用。** 当前 profile 的 `disabledSkills` 记录名称、范围、工作区根及显示需要的简介、来源、provider、path、origin，不保存技能正文。

限制按「范围＋工作区根＋技能名」区分。关闭用户技能限制它的全局来源；工作区中的同名副本仍保留原生优先级。关闭工作区 A 的技能只限制工作区 A，工作区 B 和用户范围的同名条目不随之关闭。旧记录缺少范围时，根据已有工作区来源与原生技能路径恢复可确定的工作区根；无法确定的旧记录须保持明确、可处理的状态，不猜测工作区。

开启态表示 DSH 原生目录中至少一条调用路径可用：`modelInvocable || userInvocable`。只有用户可调用或只有模型可调用的技能依然显示开启；重新启用只移除 Mod 限制，不强改作者调用策略。提供方已经双向禁用的技能显示关闭、开关不可用；不能通过本页强行开启。切换范围或工作区后重新读取完整原生目录，不把用户命令菜单中经过筛选的清单当作管理目录。

插件内置技能和普通文件技能通过同一原生注册表限制，不写入安装目录或修改 `SKILL.md`。当前核实支持 0.2.2-rc.1 的 standard、ptc、cordis 等共享 Host 技能注册表的官方组合；自定义隔离服务仍需明确报告不可管理。更近层的自定义来源按原生作用域规则处理，不声称通用控制所有外部 provider。

## 原生生效机制

[技能策略](skill-policy.ts)通过公开 `skills.registerProvider(create)` 贡献调用策略：停用候选的 invocation 两字段均为 false，加载结果正文为空且两字段仍为 false。DSH 原生模型目录、skill 工具与 `/name` 用户注入分别检查这些字段，由原生消费链拒绝，不是只隐藏 Mod 列表。

同一层按 rank 选胜者，较近作用域优先于祖先。用户限制采用位于工作区 100/200 与用户、内置来源之间的优先级，让同层工作区副本继续胜出；工作区限制只在查询 cwd 属于匹配工作区根时提供，使用足以覆盖该工作区来源的优先级。无 cwd 的用户查询不加入工作区限制。Agent 精确层只放工作区限制，避免用户限制抢过祖先层的工作区副本。

- `agents.list()` 枚举已有 live Agent；全局串行 `agent/created` 监听覆盖新 Agent；`agent/disposed` 清理对应记录。
- `agentPresets.acquireScope(id)` 提供后台目录使用的 preset 代租约；宿主同一份 `dsh-scope.createScope(ModContext, lease.key)` 创建 Mod 拥有的同 key 辅助作用域。模式信息不进入用户管理分类。
- 不在 apply 中等待 Loader settle；在公开 `loader.await()` 后后台准备保存限制需要的作用域。真实 plugin-manager 变更及后续读取更新代，释放旧辅助作用域与租约。
- 公开 `control.invalidate()` 清原生目录缓存。恢复调用时只移除对应范围记录，不复制技能正文，不改作者调用规则。

原生 `/` 菜单有独立缓存，未提供专用失效 API，刷新界面可更新旧候选；不得伪造 `plugin-manager/changed`。实际用户技能注入发生在 Agent 创建后的 pre-step，仍按当前调用策略检查。限制不撤回已经注入的正文或已经开始的调用，也不是禁止普通文件工具读取该文件的安全沙箱。

## 从其他 Agent 导入

### 来源关系与添加交互

页面标题下，全局与工作区显示「DSH 自动读取 .dsh 和 .agents 中的技能」，发现页显示「从其他 Agent 导入技能」。页面说明只用 `.dsh`、`.agents`，不追加 `skills` 层级；详情中的真实文件路径仍完整显示。

每个全局或项目范围内按技能名组织卡片。卡片不展示 Agent 名称徽标、内容关系、复制／链接状态或技术说明；底部沿用管理卡片的等宽目录简称，例如 `.codex`、`.agents`。多个不同来源路径在同一个目录标注后增加最多两层轻量堆叠，后层向右上方每层错开 4px，顶部和右侧各预留 8px，不挤压目录文字；不逐个平铺标签或另占一行，悬停或键盘聚焦显示所有完整路径。相同真实路径合并为一个候选但保留全部路径；不同真实路径的副本通过整个技能包指纹比较。名称仅用于调用和分组，候选 id 包含路径身份，指纹用于版本校验；不能仅以名称判断唯一。

用户只看到一个写入操作「导入」，内部固定使用复制，不展示复制／软链选项、下拉操作菜单或「选择来源」按钮。单一内容直接进入目标确认，相同内容的多个路径无需选择。不同内容时，点击导入先打开简洁详情弹窗，只在「路径」一行使用原生 Menu 选择实际路径，正文读取完成后以「导入」进入目标确认；不显示单来源 radio 列表或重复的路径区块。

发现页保留所有已发现技能，包括 DSH 当前范围已有的技能。已有项保持正常卡片文字和目录样式，只在名称右侧标注次要色普通文字「已存在」，底部只保留「详情」，不渲染导入按钮；分组数量包含这些已有项。状态直接从本次 DSH 原生目录判断，不依赖导入记录，也不把未读取成功的目录当作不存在。同名不同内容另保留冲突原因，绝不覆盖。只有全局存在同名技能时，项目范围仍允许导入，确认时说明项目优先使用。

导入前重新检查来源身份、指纹、目标是否存在和权限，拒绝过期选择与覆盖。复制整个技能包，包内链接仅允许安全保留在包内，无法保证完整复制时拒绝，不静默丢弃资源。写后使原生目录失效并读回，只有 DSH 确认识别预期位置后显示成功；所有来源卡片保留，目标范围已有的卡片标注「已存在」，随后重读各组原生状态，数量不因导入减少。成功只显示一次「导入成功」，约 3 秒后消失，不提供「查看」、跳转、搜索或定位；留在发现页。DSH 副本被外部移除后，再次扫描恢复导入按钮。

不再读取或写入额外导入记录，不维护来源基线或更新历史；原生目录是已存在状态的唯一依据。导入仍使用暂存、版本复核、不覆盖发布和原生读回保护；旧记录文件不自动删除，已有技能和源目录不受影响。移除依赖历史记录的受管更新接口，不自动更新、覆盖、修复或删除技能。读取、重试、导入和卸载沿用共享错误反馈与过期响应隔离，失败保留选择和卡片。

技能页在「全局」「工作区」之后增加独立「发现」Tab，Tab 下方沿用通栏搜索框。搜索按技能名、描述（含不同来源版本）、来源名称与所有来源路径筛选，忽略大小写及首尾空白，只过滤已扫描数据，不因输入重复扫描。搜索期间展开命中分组，数量显示匹配项数（含已存在项），完整扫描且无匹配的分组隐藏；清空后恢复手动折叠状态。无匹配时整页只显示一次搜索空态，加载、失败与目录不完整的反馈仍保留。

进入发现时分别扫描全局与每个已登记项目，平铺为独立可折叠分组。标题采用 chevron + 名称 + 发现总数，不显示分组描述；项目路径通过悬停展示。默认展开并保留手动折叠，数量包含已存在卡片，不因导入减少。首次加载或失败且无旧目录时不显示数量；刷新保留已确认的卡片与数量，各组错误独立反馈和重试。

扫描完整且没有发现任何技能时隐藏分组；即使组内全部技能已存在，也保留卡片和数量。所有分组都没有发现结果时，整页只显示一次「未发现技能」。加载、错误、目录不完整或尚有操作错误的组保留反馈，不冒充空组。

- 每个目录按原生技能格式识别 `<name>/SKILL.md` 与 `<name>.md`；读取 frontmatter 的名称与简介用于列表，并对整个技能包执行有界指纹比较。正文只在详情请求时作为文本返回，不随列表发送。名称须符合原生 kebab-case，隐藏目录与 `.system` 等点开头条目跳过。单个源根最多 4096 个目录项，最多 400 个技能候选；单个包最多 512 个条目与 50 MiB，单次比较总预算 4096 个条目与 256 MiB。缺失源目录视为空，访问失败明确报错，超出内容预算的候选显示无法完整比较并禁止添加。
- 条目本身是符号链接时跟随读取，以真实路径合并候选并保留所有 Agent 位置。不同目录的同名副本在同一张卡片中按完整内容指纹比较，选择项保留实际路径，以支持明确选择链接目标；内容指纹包含排序后的相对路径、条目类型、文件长度和字节，不把内容相同当作永久身份或作者身份。
- 点击「导入」先打开小型确认弹窗，只提供「导入到」一个原生下拉，选项为全局和已登记工作区，默认选择卡片所属分组；下方显示 Host 确认的最终完整路径，底部「取消／导入」。全局固定使用当前 profile 的技能根，项目固定使用 `<项目根>/.dsh/skills`，不增加目录、复制或链接选择。不同内容仍先在详情路径字段选择版本，再进入同一个目标确认弹窗；详情和确认弹窗不同时显示。
- 源范围与目标范围独立传递：从源范围重新验证选中版本，再按目标范围检查原生目录、磁盘占用与最终读回；目标可不包含任何外部来源，也可与源分组不同。目标切换时重新读取真实路径、已有状态和全局同名提示，旧响应不能覆盖新选择，未完成或读取失败时禁止确认。只允许当前已登记工作区或全局，项目根遵循原生 `.git` 祖先规则。DSH 已有同名技能或目标被占用时不覆盖；失败保留目标选择并提供共享错误反馈与重试。
- 复制包含 `references`、`scripts`、`assets` 的完整包，跳过 `.git`、`.DS_Store`；包内链接只允许真实目标仍在包内并以可迁移相对链接保留，外部或断裂资源链接拒绝，不静默跳过。复制使用隐藏暂存、指纹复核与不覆盖发布，链接直接指向真实源路径；任何目标同名目录、扁平 Markdown 或断裂链接均视为已占用。
- DSH 同范围已识别的技能保留并标记 `available`，已关闭调用的技能也视为已存在。名称相同但内容不同或无法比较时另保留 `conflict`，不覆盖；仅磁盘占用但尚未被 DSH 识别时标记冲突，不假称可用。
- 卡片复用技能卡片样式与双列网格：标题、最多两行简介，底部左侧为目录简称及多路径堆叠、右侧为「详情」「导入」；没有单独的来源徽标行。详情完整展示描述。
- 「详情」按需读取源 `SKILL.md` 正文，使用与已装技能相同的详情 `Modal` 和 Markdown 渲染，不写入任何文件、不产生导入。
- 「导入」逐条执行，不提供批量；仅在目标确认后写入，进行中禁止重复提交、切换目标和关闭弹窗。成功保留来源卡片和组数量，重新扫描各范围的已有状态，只短暂显示「导入成功」。失败保留目标和来源版本，弹窗复用共享错误反馈；写入成功但原生未识别时明确说明需要核对管理页，不声称成功也不重复写入。
- 分组读取失败在该组内使用共享错误反馈并提供定向重试；添加失败保留卡片、来源选择与可恢复状态。离开「发现」Tab 后保留扫描结果，再次进入重新扫描。添加进行中禁止重复操作和重新扫描，迟到的扫描与详情响应不能覆盖新结果；项目添加后重读该项目已加载的技能目录，不刷新或移除其他项目的卡片。
- 不扫描任意路径、不接收用户输入的源目录、不联网、不安装依赖；不读取或写入其他 Agent 的配置。

## 详情弹窗

每张技能卡片底部左侧显示来源目录简称，右侧是「详情」文字按钮；无法从公开元数据确认来源时不猜测、留空。路径、简介和正文在弹窗中按需展示。按钮与 MCP 详情同一套规格（28px 高、`--dsw-radius-sm`、0.5px 描边、hover `interactive-bg-hover-solid`），可访问名称包含技能名并关联只读原因。

点击打开宿主公共 `Modal`（宽 `min(560px,100%)`）：标题「技能详情」，说明为技能名，默认聚焦「关闭」。管理详情在可删除时增加「删除／移除链接」；发现详情只有尚可导入时增加「导入」，已有技能不显示状态文字或占位按钮。正文按固定顺序组织：

1. 路径：完整显示实际文件路径，相同内容的多来源逐行显示于同一个字段。只有不同内容需要在此字段选择路径；不重复显示 Agent 名称、真实路径解释、目标目录、文件关系或来源提示段落。
2. 描述：与路径共用只读两列 `dl`，标题样式和两列对齐方式一致。完整显示 frontmatter 描述，左列标题「描述」，右列内容为 13px／20px 次要色，保留换行，不截断、不要求悬停查看。
3. 正文：直接复用宿主公共 `MarkdownText`，使用 `compact` 排版与 `omitHtml: true`。标题、列表、强调、表格和代码块按宿主规则展示，HTML 不作为标记执行或显示；代码复制与脚注文案由技能 locale 提供。不增加第三方依赖或自写 Markdown 解析器，不加「正文」标题或整块代码框；没有正文时显示「此技能没有正文内容」。

三段共用一个最大高度 `min(60vh,560px)` 的可聚焦滚动区，正文顶部用主题分隔线与简介／路径分开，内容可选择复制。弹窗标题与关闭按钮保持在滚动区外。

正文经 owner-only RPC `readSkill(cwd, scope, name)` 按需读取，使用与目录相同的 preset 作用域。只返回名称、简介、正文、来源、路径、目录或插件包与调用标志，不返回历史来源、额外源正文或 provider 私有 locator。非法技能名拒绝，条目已不在原生目录中则返回 `null`。加载复用共享反馈；失败在弹窗内使用产品摘要 `skillDetailFailed` 与 `PD-SKILLS-DETAIL` 错误反馈，可就地重试，不显示传输层原始文本。关闭不刷新目录、不写入状态，迟到响应丢弃；正文不持久化。

目录首次加载或范围／工作区切换后无目录时，通过共享 `loadingFeedback({ label: t('loading') })` 显示公共 `StateDot` 的 `ongoing` 加载反馈；同一范围与工作区重新加载时保留旧列表，使用 `compact: true` 的紧凑反馈。切换上下文仍清除旧目录，过期响应隔离不变。目录加载错误放在标题之后、范围和搜索之前；卡片操作错误留在相应控件旁。工作区分组遵循同一规则：首次展开无目录时显示整段加载反馈，重读保留旧列表并用紧凑反馈；组内加载错误用共享反馈并可重试，不把失败显示为空分组。两者复用[统一错误反馈](../../../docs/error-handling.md)，提供安全错误信息与复制；加载可显式重试，失败仍保留原有上下文、已确认数据与写入限制。

## 持久化与操作

### 删除技能

全局与工作区技能详情底部提供「删除」，发现页的来源详情不删除外部文件。仅允许当前 profile 的技能根、当前已登记项目 `.dsh/skills` 内实际列出的直属技能目录或扁平 Markdown；`.agents`、`.codex`、自定义目录与内置提供方不提供删除。技能根或项目 `.dsh` 经过符号链接指向共享位置时也不开放删除。根路径从 Host 上下文推导，不接受 Client 指定任意磁盘路径。

详情返回可选 `deletion: {path, linked, revision}`，指纹绑定实际文件身份与目录内容元数据；无法确认完整目录或文件身份时保留查看能力，不提供删除。目录链接显示「移除链接」，只移除链接本身，不跟随删除源目录。删除点击后用同一 Modal 切换为确认状态，完整显示目标路径，说明目录及其资源会删除、操作不可撤销；链接说明保留源文件，默认聚焦取消。不新增卡片按钮、回收站或历史记录。

`deleteSkill(cwd, scope, name, revision)` 复用 owner-only 串行队列，写前核对当前登记项目、完整原生目录、DSH 自有根、实际路径和确认指纹；外部替换或修改后拒绝过期确认。目标先移动到同目录隐藏暂存并再次核对身份，再移除；包内链接不跟随，校验或取消失败尽量恢复原位置，不覆盖外部新文件。删除前移除本技能对应范围的停用记录，避免原生目录保留虚假条目，其余偏好保持。失败保留详情、确认路径及共享错误反馈，可刷新详情重新确认。写入中禁止关闭、重复提交及切换范围；成功关闭弹窗、重读管理与已扫描发现目录，外部来源仍在时恢复可导入状态。没有独立增强开关，随技能管理入口管理。

发现卡片上的「已存在」位于名称右侧，采用次要色普通文本，没有按钮边框或交互语义；已有条目不渲染导入按钮，详情保持可用，卡片不整体置灰。来源详情不重复状态文字，目标确认遇到占用只提示「请选择其他导入位置」，不显示「已存在」按钮或标签。

owner-only RPC 包含目录／详情／启停、发现／来源详情、兼容复制导入与 `addSkill(cwd, scope, id, mode, revision)`；scope 为 user 或 project，mode 保留 copy／link 的底层能力，当前 UI 固定 copy。`readSkillImportDestination(cwd, scope, name, flat)` 只返回目标完整路径、完整性、已有状态及全局同名提示，不写盘；`importSkillTo(cwd, scope, id, revision, targetCwd)` 分别验证来源与目标，空 targetCwd 表示全局，其余必须是已登记工作区。发现响应的 `available` 来自原生目录，`conflict` 来自名称、内容比较和目标占用；不发送导入历史或随列表发送正文。非法范围、未登记项目、不可用上下文、不完整目录、过期指纹、已存在和同名冲突均拒绝写入。旧复制 RPC 同样重新发现并验证原生读回。

所有操作共用已有串行队列。通过宿主 `configEditor.edit` 只更新对应范围记录，保留其他偏好与其他工作区；不能手写 profile patch。写后重新查询原生 snapshot 核对实际调用状态。失败重新读取事实；同值请求不写入。读取失败不显示为空目录，目录不完整禁止操作；请求中禁止重复提交或切换写入上下文，过期响应不能覆盖新上下文。

入口 `skillManagerEnabled` 与技能限制分别持久化；账号、遥测开关保存须保留这些字段。provider、监听、辅助作用域和 lease 随 Mod 或相关 Agent 卸载释放；卸载后不得继续写配置。
