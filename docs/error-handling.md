# 错误处理规范

本文是 PowerDSH 全部功能的错误处理主规范，覆盖设置、管理列表、编辑器、侧栏与后台操作；各功能 Spec 只补充本功能的恢复条件。它属于现有功能的基础行为，不另设开关或日志查看器。页面几何与主题参照见 [UI 规范](ui.md#状态提示与错误反馈)，开发检查见[开发指南](development.md#协作流程)。

## 展示与恢复

- 页面加载或依赖失败：在标题说明后、内容控件前显示共享错误反馈；只保留错误文字、详情与必要重试，不套卡片或大块背景。保留已确认的数据，禁止依赖失败数据的写入，不显示假空列表。
- 保存或校验失败：反馈留在对应设置行、卡片或编辑器旁，通过 id、`aria-describedby` 和 `aria-invalid` 关联控件；保留草稿及原生读回状态。
- 侧栏等紧凑入口：保留所在位置的紧凑容器，内部复用相同错误摘要与原生详情弹窗，不另造全局通知。
- 详情弹窗等模态场景：使用共享反馈的 `modal` 形态，以浅错误底、内边距与圆角的横幅单行展示，摘要居左，重试与详情按钮靠右同行（重试在前）；窄容器内摘要自行换行，按钮组不换行错位。摘要固定为产品文案，不显示 RPC 传输层包装或原始异常文本。其余摘要、详情、复制与恢复交互不变。
- 摘要使用简短、可处理的双语文案和原生错误色；加载、只读、条件未满足等正常状态不冒充错误。成功后移除过期反馈，正常成功不弹提示。
- 摘要与轻量「详情」入口同行，窄容器可换行；点击详情才打开宿主公共 Modal 查看并复制诊断，不在设置行内展开大块文本。入口具有 `aria-haspopup="dialog"` 和 `aria-expanded`，默认关闭；关闭后保留本次诊断与复制状态，错误身份改变时关闭并重置。详情采用普通文字色、等宽字体、保留换行，长内容有界滚动；按钮使用公共组件，弹窗的焦点、Escape 与关闭恢复交给宿主。剪贴板不可用或复制失败时明确提示，并保留可选择复制的文本。
- 仅提供业务允许的重试动作；已有清晰的原操作入口可重试时，不重复添加按钮。重试沿用原操作的权限、忙碌与上下文检查，不自动重放保存、启动进程或其他外部副作用；不得用无限重试掩盖错误。

## 信息与隐私

每个反馈具有稳定错误代码和操作标识。设置保存失败与功能运行失败分别归类，功能失败不冒充保存失败；同一行真实保存失败优先展示，不能带上先前运行失败的原因。详情包含产品名、代码、操作、错误摘要、观察时间及已确认的 DSH 版本与平台；未知信息省略，不伪造原因。功能可补充明确选取的 Stage、Check、Result、Expected、Actual、State、Recovery 字段：阶段与结果保留稳定机器标识并可附本地化解释，检查项使用代码中定义的语义标识，预期值与实际结果限于数量、已知状态或允许的布局枚举，便于直接复制给 AI 或维护者定位。不得把原始类名、DOM 或 CSS 正文当作检查结果。已知的业务失败优先映射到产品文案，未知失败保留通用摘要；只有现有错误信息不足以定位关键意外故障时，才按需补充日志。

显示、复制与记录前统一处理文本：限制长度，移除控制字符，隐藏 URL、认证头、常见凭据赋值与机器绝对路径。诊断只组装明确字段，不序列化异常对象、请求参数、配置、命令、环境、响应正文、会话内容或编辑器草稿。文本脱敏是补充防护，不允许把整个配置交给脱敏器后当成安全数据。原始异常消息或堆栈不直接跨 RPC 展示。

已知运行失败的观察时间记录在原因首次出现时，同一原因重复检查、展开或复制不改写时间；原因、检查项、结果或观察时间变化时重置详情与复制状态，旧复制完成不能更新新诊断。恢复建议按失败原因选择：异步样式或布局变化可自动复查；不支持或歧义提示更新及重新加载；初始化意外失败允许用户切换开关重试，持续失败时引导复制诊断，不承诺重试一定恢复。

涉及多个外部步骤的操作须在发生失败的边界保留具体阶段与已确认结果，不能只把同一句产品提示再复制进诊断。更新检查分别记录 Git 查找、远端标签、正式 Release、安装包与市场接口阶段；有结果时附 HTTP 状态、进程退出码、耗时及白名单网络／证书错误码，失败时间随结果传递到 Client。协议只接受固定阶段／原因、受限数值与已知系统码，不传 Git stderr、远端响应正文或原始异常；旧 Host 未提供原因时明确说明诊断缺失，不推测网络故障。其他功能按同一共享诊断字段选择自身有用证据。

错误详情为当前反馈的状态，不建立跨会话历史；页面卸载或恢复后释放。复制成功与失败只影响复制操作，不覆盖业务失败。旧请求、卸载后的响应以及过期复制结果不得覆盖新反馈。

## Host 与日志

日志按排障需要使用，不要求每个错误都记录，不为全部 Host 方法增加统一包装或专用分类层。关键操作发生意外故障、且有明确的信息可帮助定位时，可直接复用宿主 logger 记录一次；输入校验、用户取消和预期的权限拒绝通过界面说明，不记为 error 日志。

按需日志仅记录操作及安全原因，不记录参数、配置、原始异常对象或堆栈；不逐层重复记录。日志不可用不能覆盖原来的业务错误。失败仍由功能自身明确传播、保留状态并提供恢复方式。

不建立日志中心、历史存储或新日志文件，不扫描个人日志或上传。DSH 原生 logger 通道不保证普通错误落盘；插件安装日志和 Session 日志分别服务于包操作与会话历史，不能当作 PowerDSH 运行错误历史。

## 实现与验收

界面使用 [共享错误反馈](../src/shared/client/error-feedback.ts)，文本使用 [诊断处理](../src/shared/types/diagnostics.ts)。新增功能不得另写孤立的错误样式或只输出「请重试」。跨功能要求通过共享层维护，不把 MCP 的状态或错误代码复制到其他功能。

必要验收覆盖：真实失败与空态区分、页面和行内位置、浅深主题与双语、长文本换行、详情展开、复制成功/拒绝/不可用、恢复与卸载、并发旧响应、无敏感参数进入诊断；确有按需日志的功能还应验证日志失败不改变原始错误。静态检查约束运行源码中的错误反馈归属，行为测试验证恢复与数据保留；构建与测试不替代实际宿主及 Windows 验收。
