# 技能管理

模块 id：`skills`；主开关 `skillManagerEnabled` 默认 `false`。模块的[定义](definition.ts)、[配置](config.ts)、[Client](client.ts)与[行为测试](tests/)在本目录维护。

## 入口与范围

在 **设置 → PowerDSH → 管理** 打开「技能管理」，原生设置侧栏新增独立「技能」页。入口开关默认关闭、独立持久化；只控制管理页的显示。关闭入口不会恢复已停用技能；停用或卸载整个 Mod 则释放它的运行时限制，技能回到提供方原有规则。重新加载 Mod 后恢复已保存的停用名单。

页面复刻原生内置插件布局：顶部功能说明、**全局／工作区** Tab、搜索、折叠分组和双列技能卡片；窄容器单列。卡片直接在右上角提供启停开关，不展开收起。顶部只显示功能说明「管理 DSH 中可用的技能」，用户分组说明为「从本机技能目录加载」，内置分组说明为「随 DSH 或插件提供」；不增加目录提示或感叹号；技能简介按原生插件卡片最多两行、悬停读全文；同一行卡片等高、底部详情按钮对齐，外层内容滚动区预留稳定滚动槽，避免滚动条出现时宽度跳动，尺寸与主题见 [UI 规范](../../../docs/ui.md#技能与-mcp-管理列表)。全局按「用户」「内置」顺序分组：运行时和 bundled 来源归内置，用户、自定义目录及其他来源归用户；没有来源筛选下拉，卡片不重复显示来源标签，底部只提供右对齐的详情按钮。用户默认展开，内置默认收起；搜索自动展示匹配分组，清搜索恢复手动折叠状态。工作区范围将已导入工作区的名称下拉与搜索放在同一行，下拉在左、搜索在右，不再显示「全部来源」下拉，同样展示技能卡片。模式只作为后台目录加载上下文，页面不提供模式选择。MCP 使用[独立管理页](../mcp/spec.md)，不增加安装、编辑、删除、导入或导出。

- 全局目录调用原生 snapshot 时不传 cwd，原生 filesystem provider 因此只加入用户、自定义、内置等非工作区来源。不能先读取当前工作区的合并结果再过滤，否则工作区的同名技能会遮住用户副本。
- 工作区目录带明确的工作区 cwd，并只展示工作区来源。工作区下拉复用原生模式选择器相同的公共 `Menu`，触发按钮、选中勾、键盘及关闭交互遵守 [UI 下拉规范](../../../docs/ui.md#下拉选择)；仅列 Host `workspaceRegistry.list()` 中已经导入的工作区，响应只投影 `{path,title}`：显示已保存的工作区名称，路径作为选择值和悬停说明，同名工作区用路径辅助区分。即使只有一个工作区也保留下拉；无工作区显示「暂无已导入工作区」，不执行工作区目录读取。默认工作区优先取已导入且匹配 `workingDirectory.defaultDirectory` 的项，否则取导入列表首项，不把未导入的启动目录加入选项。`workspaces` 是 Client 服务名，不能用于 Host 接线。
- 工作区根遵循原生 filesystem 语义：最近的 `.git` 所在祖先，否则使用所选 cwd。工作区子目录共享同一个工作区的限制；两个独立工作区互不影响。

## 来源元数据

来源保留目录简称（如 `.dsh`、`.agents`、`.codex`）与可确认的提供包身份，供 Host 元数据投影使用，不常驻卡片或详情弹窗。完整技能路径在详情弹窗显示，缺少文件路径时可使用公开的目录资源根。卡片简介最多两行，完整原文通过原生 `Tooltip` 显示，提示以 portal 呈现，避免被卡片裁剪，规则见 [UI 悬浮提示](../../../docs/ui.md#悬浮提示tooltip)。卡片右上角开关为 28×16px 小号尺寸，主题与交互沿用原生。

[来源解析](skill-origin.ts)直接使用 DSH 公共目录中的来源、文件路径及目录资源根。原生来源保留 `.dsh`、`.agents` 语义；其他提供方的文件技能从已有绝对路径中的 `.目录名/skills` 识别简称，不硬编码某个第三方插件的 source、接口或数据结构，不新增目录扫描。DSH 原生默认扫描 `.dsh`、`.agents`；当前 `.codex` 条目由已启用的第三方提供方注册进统一目录，Mod 只展示该目录的结果。内置来源使用已核对的 provider 对应关系，或公开路径中最近 `node_modules` 包的真实 manifest name。Office 的 `dsh-office` 和 Badge 的 `dsh-badge` 已按安装版 0.2.2-rc.1 源码核对；Office 资源根可以独立配置，因此不能假定其路径包含包名。未知来源不按技能名猜包名，不读取技能正文。来源字段 `origin` 是显示元数据，不改变分组、调用策略或读取范围；停用时保存，重载后保留。

## 只对 DSH 生效

**单项开关控制 DSH 的技能调用能力，不修改共享技能文件，不影响其他应用。** 当前 profile 的 `disabledSkills` 记录名称、范围、工作区根及显示需要的简介、来源、provider、path、origin，不保存技能正文。

限制按「范围＋工作区根＋技能名」区分。关闭用户技能限制它的全局来源；工作区中的同名副本仍保留原生优先级。关闭工作区 A 的技能只限制工作区 A，工作区 B 和用户范围的同名条目不随之关闭。旧记录缺少范围时，根据已有工作区来源与原生技能路径恢复可确定的工作区根；无法确定的旧记录须保持明确、可处理的状态，不猜测工作区。

开启态表示 DSH 原生目录中至少一条调用路径可用：`modelInvocable || userInvocable`。只有用户可调用或只有模型可调用的技能依然显示开启；重新启用只移除 Mod 限制，不强改作者调用策略。提供方已经双向禁用的技能显示关闭、开关不可用；不能通过本页强行开启。切换范围或工作区后重新读取完整原生目录，不把用户命令菜单中经过筛选的清单当作管理目录。

插件内置技能和普通文件技能通过同一原生注册表限制，不写入安装目录或修改 `SKILL.md`。当前核实支持 0.2.2-rc.1 的 standard、ptc、cordis 等共享 Host 技能注册表的官方组合；自定义隔离服务仍需明确报告不可管理。更近层的自定义来源按原生作用域规则处理，不声称通用控制所有外部 provider。

## 原生生效机制

[技能策略](skill-policy.ts)通过公开 `skills.registerProvider(create)` 贡献调用策略：停用候选的 invocation 两字段均为 false，加载结果正文为空且两字段仍为 false。DSH 原生模型目录、skill 工具与 `/name` 用户注入分别检查这些字段，由原生消费链拒绝，不是只隐藏 Mod 列表。

同一层按 rank 选胜者，较近作用域优先于祖先。用户限制采用位于工作区 100/200 与用户、内置来源之间的优先级，让同层工作区副本继续胜出；工作区限制只在查询 cwd 属于匹配工作区根时提供，使用足以覆盖该工作区来源的优先级。无 cwd 的用户查询不加入工作区限制。Agent 精确层只放工作区限制，避免用户限制抢过祖先层的工作区副本。

- `agents.list()` 枚举已有 live Agent；全局串行 `agent/created` 监听覆盖新 Agent；`agent/disposed` 清理对应记录。
- `agentPresets.acquireScope(id)` 提供后台目录使用的 preset 代租约；宿主同一份 `dsh-scope.createScope(ModContext, lease.key)` 创建 Mod 拥有的同 key 辅助作用域。模式信息不进入用户管理分类。
- 不在 apply 中等待 Loader settle；在公开 `loader.await()` 后后台准备保存限制需要的作用域。真实 plugin-manager 变更及后续读取更新代，释放旧辅助作用域与租约。
- 公开 `control.invalidate()` 清原生目录缓存。恢复调用时只移除对应范围记录，不复制技能正文，不改作者调用规则。

原生 `/` 菜单有独立缓存，未提供专用失效 API，刷新界面可更新旧候选；不得伪造 `plugin-manager/changed`。实际用户技能注入发生在 Agent 创建后的 pre-step，仍按当前调用策略检查。限制不撤回已经注入的正文或已经开始的调用，也不是禁止普通文件工具读取该文件的安全沙箱。

## 详情弹窗

每张技能卡片底部只保留右对齐的「详情」文字按钮，**不再常驻显示来源标签**，路径、简介和正文在弹窗中按需展示。按钮与 MCP 详情同一套规格（28px 高、`--dsw-radius-sm`、0.5px 描边、hover `interactive-bg-hover-solid`），可访问名称包含技能名并关联只读原因。

点击打开宿主公共 `Modal`（宽 `min(560px,100%)`）：标题「技能详情」，说明为技能名，底部只有「关闭」按钮并默认聚焦。正文按固定顺序分三段：

1. 路径：只读两列 `dl` 中的唯一一行，即 `SKILL.md` 的实际位置——卡片无法显示、也最需要在打开文件前确认的事实。路径为空时整块省略。**不重复显示来源、开关与两条调用链**：来源已由页面的用户／内置分组表达，开关状态就在卡片右上角，再列一次只会挤占正文空间。
2. 简介：`SKILL.md` frontmatter 的描述，13px／20px 次要色，**最多两行、超出省略**，完整原文经 `title` 悬停查看。简介只作引入，正文才是打开弹窗的目的。
3. 正文：`SKILL.md` 的 Markdown **原文**，**不加「正文」等标题**，直接作为弹窗主体。不做 Markdown 渲染：不依赖宿主内部渲染组件，也不引入新依赖，避免渲染器版本、GFM 扩展或插件配置差异带来的不兼容；显示的就是技能实际加载的正文，不会因渲染而丢失或改写内容。仅做两处与安全无关的整理：去掉 HTML 注释（版权与来源声明，夹在正文中会埋没后续说明），并把连续空行折叠为一个。等宽字体保留换行、可选中复制，最大高度 `min(48vh,420px)` 内部滚动并可键盘聚焦；没有正文时显示「此技能没有正文内容」。

正文经 owner-only RPC `readSkill(cwd, scope, name)` 按需读取，使用与目录相同的 preset 作用域，因此项目副本与列表行解析一致。响应只含名称、简介、正文、来源、路径、目录或插件包与两条调用标志，不返回 provider 私有 locator 或其他技能字段。技能名必须匹配原生命名规则，否则拒绝；条目不在当前目录中时返回 `null`。读取失败在弹窗内复用[统一错误反馈](../../../docs/error-handling.md)（代码 `PD-SKILLS-DETAIL`）并可就地重试。关闭只收起弹窗，不刷新目录、不改变技能状态、不写入偏好；关闭后到达的响应不再更新弹窗。正文不缓存，也不写入任何位置。

目录加载错误放在标题之后、范围和搜索之前；卡片操作错误留在相应控件旁。两者复用[统一错误反馈](../../../docs/error-handling.md)，提供安全错误信息与复制；加载可显式重试，失败仍保留原有上下文、已确认数据与写入限制。

## 持久化与操作

owner-only RPC 为 `listSkills(cwd, scope)`、`readSkill(cwd, scope, name)` 和 `setSkillEnabled(cwd, scope, name, enabled)`，scope 为 user 或 project；首次空值默认 user。响应只包含 cwd、scope、工作区列表、完整性和白名单技能字段，不公开 preset 选择，不发送正文或 provider 私有 locator。非法范围、未注册工作区、不可用的后台上下文、非法技能名及不完整目录均拒绝写入。

所有操作共用已有串行队列。通过宿主 `configEditor.edit` 只更新对应范围记录，保留其他偏好与其他工作区；不能手写 profile patch。写后重新查询原生 snapshot 核对实际调用状态。失败重新读取事实；同值请求不写入。读取失败不显示为空目录，目录不完整禁止操作；请求中禁止重复提交或切换写入上下文，过期响应不能覆盖新上下文。

入口 `skillManagerEnabled` 与技能限制分别持久化；账号、遥测开关保存须保留这些字段。provider、监听、辅助作用域和 lease 随 Mod 或相关 Agent 卸载释放；卸载后不得继续写配置。

## 接口依据与验证

接口依据为 DSH `0.2.2-rc.1` 安装包公开实现：`dsh-skill` 的分层目录与 rank、`dsh-skill-filesystem` 在 cwd 缺省时不添加工作区根的行为、`dsh-scope` 的上下文所有权及原生技能三条消费链的调用策略检查。市场与同类源码的确切提交、MIT 许可及参考边界见[来源研究](../../../docs/third-party-notices.md#技能与-mcp-来源研究)，没有复制或改编参考实现。跨版本结论见[版本兼容性](../../../docs/compatibility.md)。

[Host 接线测试](../../../tests/integration/host-wiring.test.mjs)用实际 Cordis injector 加载 Mod；[策略测试](tests/skill-policy.test.mjs)覆盖目录范围、同名技能、工作区隔离、作者规则、失败与生命周期，包括首次租约无 key 时的作用域创建、复用及重复租约释放；Client 测试覆盖两个范围、工作区选择、过期响应和写入期间限制。额外用真实 SkillRegistry/Cordis 做纯内存验证，不改变用户真实技能或 profile。

这些检查不等于实际 GUI、真实模型请求或整机重启验收。交付时分别记录插件加载和未验证的界面行为。
